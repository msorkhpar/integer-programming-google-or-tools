  16. Vectors, matrices and Ax ≤ b

GridCap's finance team liked the plan from lesson Decisions, objectives and constraints: turning a planner's question into a model: fund P001, P002, P005 and P006. The plan is worth $3,627k and costs $7,100k, which fits the $7,390k capital budget with $290k to spare. Then they asked a question the one-number budget could not answer: does it fit each year? GridCap's budget is set year by year, $2,300k for 2027, $3,280k for 2028 and $2,310k for 2029. A project spends its cost over the years it is worked on, so checking the plan means one sum per year, and a real model has hundreds of rows. This lesson writes a plan as a vector and the rules as a matrix, so that one line of NumPy checks every rule at once. Five rules, one per heading.

A vector here is an ordered list of numbers, one per project; a matrix is a table of numbers with rows and columns. NumPy (import numpy as np) stores both as arrays and does arithmetic on whole arrays at once. GridCap is a fictional utility; none of its numbers describe a real one.

A Plan Is a Vector, and Its Value and Cost Are Dot Products

Lesson Decisions, objectives and constraints: turning a planner's question into a model wrote a plan as a 0/1 vector $x$, one entry per project. The data become vectors the same way: capex holds each project's cost and npv its value, in the same project order.

capex * x multiplies entry by entry: a funded project keeps its cost and an unfunded one becomes 0. Adding those products up is the dot product, written $c^\top x$ in math and capex @ x in NumPy:

The $\top$ (transpose) only says the vector $c$ is laid on its side as a row so that it can multiply the column $x$. Both numbers from lesson Decisions, objectives and constraints: turning a planner's question into a model come back: the plan costs $7,100k and is worth $3,627k. The objective of the model is $\text{npv}^\top x$ and the one-period budget row is $\text{capex}^\top x \le 7390$.

A Budget Matrix Has One Row per Constraint and One Column per Decision

One budget per year means one dot product per year, each with its own coefficients: what each project spends in that year. Stack those coefficient vectors as the rows of a matrix $A$ and the budgets into a vector $b$. The vector $b$ is called the right-hand side, because each row's limit stands to the right of its $\le$. A project's cost profile is what it spends in each year of its work, in order: P003's is $980k in its first year and $1,490k in its second. In this lesson every funded project starts in its earliest start year, so its cost profile fixes the year each part of its cost lands in. (Section 6 lets the start year move.)

Read it by column and by row. Column P003 is the project's cost profile laid on the calendar: $980k in 2027 and $1,490k in 2028, which add up to its $2,470k capex. Row 2028 is the 2028 budget constraint: every project that spends money in 2028, with how much. The entry in row $r$ and column $j$ is written $a_{rj}$, and row $r$ of the matrix as a vector is $a_r$.

The shape is the point. A model's constraint matrix always has one row per constraint and one column per decision variable: here 3 rows by 8 columns. The variables' order is the columns' order, and it must be the same in $A$, in $x$ and in the objective vector.

Ax ≤ b Checks Every Row at Once

The product $Ax$ takes the dot product of every row with $x$, giving one number per row: the row's activity, here what the plan spends in each year. The comparison $Ax \le b$ then holds row by row:

The plan that fit the $7,390k total does not fit the year budgets. P001, P002 and P006 all start in 2028 and would spend $2,150k + $2,730k + $840k = $5,720k that year, against $3,280k. The slack $b - Ax$ says by how much each row is satisfied: positive means room to spare, zero means the row is exactly met (it is tight), and negative means the row is broken, here by $2,440k. np.all turns the row-by-row answers into one: a plan is feasible only if every row holds.

An array of True and False, like A @ x > b, is a boolean mask: one yes/no per row. np.flatnonzero(mask) returns the positions of its True entries, here [1], the second row (NumPy counts from 0). Those positions index anything in row order, such as the list of years, so the check can say which rows break and not only that some do.

GridCap's money is in whole $k, so these sums are exact. With fractions they are not, and the check needs a tolerance: a small number by which a row may miss and still count as met.

Here $A = [0.1 \;\; 0.1 \;\; 0.1]$, $x$ is all ones and $b = 0.3$. On paper the row is met exactly. In binary floating point 0.1 has no exact form, the sum lands a hair above 0.3, and the check without a tolerance rejects a plan that is fine.

Problem statement

A field-operations team plans work orders against crew-hour limits. Each row of a matrix A is one crew, each column one work order, and b holds each crew's hours. A plan x gives how many times each work order is done. The team wants a checker that says whether a plan fits, and when it does not, which crews it overloads.

Write two functions in check.py. A, b and x are NumPy arrays, and the data may be fractional.

functionreturns
broken_rows(A, b, x, tol=1e-9)the indices of the rows with $a_r^\top x > b_r + \text{tol}$, as a list of ints in increasing order
is_feasible(A, b, x, tol=1e-9)True when every row satisfies $a_r^\top x \le b_r + \text{tol}$, else False (a Python bool)

A row whose activity equals its limit holds. A row that misses its limit by no more than tol holds too, because fractional sums can land a hair off.

About four lines in total, with no Python loop over the rows.

Every Linear Rule Fits Ax ≤ b: Flip ≥ Rows, Split = Rows


A matrix check is only as good as the rows in it, and lesson Decisions, objectives and constraints: turning a planner's question into a model had three more rules. Each is linear: a sum of numbers times variables, compared with a number. Every linear rule can be written as one or two rows of the form $a^\top x \le b$:


  • A ≤ row goes in as it is. The alternatives rule $x_{P006} + x_{P007} \le 1$ is the row $(0,0,0,0,0,1,1,0)$ with right-hand side 1.
  • A ≥ row is a ≤ row times −1. Multiplying both sides by −1 flips the inequality, so $a^\top x \ge \beta$ becomes $-a^\top x \le -\beta$.
  • An = row is two rows, one ≤ and one ≥: $x_{P002} = 1$ becomes $x_{P002} \le 1$ and $-x_{P002} \le -1$.
  • Variables move to the left. The parent rule $x_{P004} \le x_{P003}$ becomes $x_{P004} - x_{P003} \le 0$, a row with a 1 and a −1.




Stacked under the budget rows, the whole tiny model is one $A$ and one $b$:



The check names the broken rows: the plan overspends 2028, and its must_P002_ge row reads $-0 \le -1$, which is false because P002 is missing. Naming every row, as lesson Decisions, objectives and constraints: turning a planner's question into a model named its rules, is what turns "infeasible" into a reason a planner can act on.


Why insist on one form? Because then one function checks any linear model, and because it is the form linear-algebra results are stated in. Solvers accept ≥ and = rows directly, so you never have to flip rows for them; the flipping is for your own checks and proofs.

Checking Many Plans Is One Matrix Product


Lesson Decisions, objectives and constraints: turning a planner's question into a model checked all $2^8 = 256$ plans in a Python loop. Put every plan in as a column of a matrix $X$ instead, and $AX$ computes every row's activity for every plan in one product:






Three NumPy details carry this. b[:, None] turns $b$ into a single column so that it is compared with every column of the activity matrix (NumPy calls this broadcasting). axis=0 makes np.all look down each column, giving one verdict per plan. np.where gives every infeasible plan a value of −1, so np.argmax can only pick a feasible one.


The answer is worth reading. With yearly budgets and every project starting as early as it can, only 8 of the 256 plans are allowed, and the best is worth $1,396k, against $3,627k with one total budget. The must-do P002 alone spends $2,730k of 2028's $3,280k, so almost nothing else fits in 2028. P001 and P002 could start in 2029 instead; a model where they may is what lesson Start-time variables x(i,t) and timing windows builds.


The product is not magic: it does the same multiplications as the loop. Its value is that the model is now data, $A$ and $b$, and a check is one line that works for any model of this form, with 7 rows or 7,000.


The Model


The selection model of lesson Decisions, objectives and constraints: turning a planner's question into a model with the single budget replaced by yearly budgets, and every rule written as rows of $Ax \le b$.


Sets. $P$ the projects; $Y$ the years (2027 to 2029 on GridCap tiny); $M \subseteq P$ the must-do projects; $C \subseteq P$ the child projects, each with parent $p(c)$; $\mathcal{G}$ the alternative groups.


Parameters. $\text{npv}_j$, the value of project $j$ ($k); $a_{yj}$, what project $j$ spends in year $y$ if it starts in its earliest start year ($k); $B_y$, the budget of year $y$ ($k).


Variables. $x_j \in \{0, 1\}$ for each $j \in P$: 1 if project $j$ is funded.

Summary


  • A plan is a vector, and its value and cost are dot products. $\text{npv}^\top x$ is the objective; $\text{capex}^\top x$ is the plan's total cost.
  • A budget matrix has one row per constraint and one column per decision. Column $j$ is project $j$ across every rule; row $r$ is one rule across every project.
  • Ax ≤ b checks every row at once. The slack $b - Ax$ shows which rows hold, which are tight and which are broken, and with fractional data the check needs a tolerance.
  • Every linear rule fits Ax ≤ b. Multiply a ≥ row by −1, split an = row into two, and move variables to the left.
  • Checking many plans is one matrix product. Plans as the columns of $X$ give $AX$, every row for every plan.

Design Note: Name Every Row


The matrix form throws names away: row 4 is just row 4. Keep a list of row names next to $A$, in the same order, from the start. A broken row then reports itself as must_P002_ge, a solver log can be matched to the rule it is about, and when section 9 asks which rules make a model infeasible, the answer is a list of names a planner can read rather than a list of numbers.
