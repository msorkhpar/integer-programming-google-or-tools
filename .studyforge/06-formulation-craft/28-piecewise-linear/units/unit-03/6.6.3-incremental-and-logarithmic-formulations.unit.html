The lambda form of lesson The lambda (SOS2-style) formulation built from binaries solved the falling-tier credit line exactly, with one binary per segment. GridCap's planners now want volume-discount curves on the medium portfolio: each of the three programs' contractors bills its total work on a curve with up to 16 tiers. That is 48 segment binaries on top of 400 project binaries, and the planners ask whether there is a cheaper way to say "the point lies on the curve". There are two, and each saves something different. This lesson builds both, checks that they are exact, and measures what each costs and saves, in four rules.

GridCap is a fictional utility's portfolio, generated for this course; the credit line and the volume discounts are invented.

The Incremental Form Fills Segments in Order, With a Binary for Each Full One

Go back to lesson Convex piecewise costs without binaries's segment variables and make them say what the credit line really does: tier 2 is used only once tier 1 is full. Write each segment's use as a fraction $\phi_k \in [0, 1]$ of its width, so

and add a binary $w_k$ for each segment but the last, meaning "segment $k$ is full and segment $k+1$ may start":

Read the two halves. $w_k \le \phi_k$: if $w_k = 1$, then $\phi_k \ge 1$, so segment $k$ is full. $\phi_{k+1} \le w_k$: if $w_k = 0$, segment $k+1$ is empty. So the segments fill strictly in order, each one full before the next starts, and every $(b, y)$ the rows allow is on the curve, whatever its shape and whatever the push. This is the incremental (or delta) form. MIT's Applied Mathematical Programming (section 9.2) writes the same rows with $\delta_k$ in units instead of fractions, $L_k w_k \le \delta_k \le L_k w_{k-1}$ for a segment of length $L_k$.

It needs $K - 1$ binaries, one fewer than the lambda form, and $2(K-1)$ rows. On the falling-tier credit line of GridCap small it returns the same plan as the lambda form (next rule's table) and fills the tiers in order:

Tiers 1 and 2 full, 95% of tier 3: $1{,}500 + 1{,}500 + 0.95 \times 2{,}000 = 4{,}900$, the draw of lesson The lambda (SOS2-style) formulation built from binaries.

The order rows are worth knowing apart from curves. Any rule of the form "stage $k+1$ may start only when stage $k$ is complete" (capacity built in stages, a contract's volume bands, a crew's qualification levels) is this pair of rows.

A Gray Code Picks a Segment With About log2 K Binaries


The lambda form spends one binary per segment to say which segment is chosen, as a list of $K$ switches with one on. A list of $m$ binary digits can name $2^m$ different segments, so $m = \lceil \log_2 K \rceil$ binaries are enough to name one of $K$ (2 for 4 segments, 4 for 16). The logarithmic form keeps the lambda weights and replaces the $K$ segment binaries by $m$ bits.


The trick is which number each segment gets. Neighbouring segments share a breakpoint, and that breakpoint must stay usable from both. That is the only reason for the ordering: it changes neither the LP bound nor the order in which the solver branches on the bits. Number the segments with a Gray code, an ordering of the $m$-bit numbers in which neighbours differ in exactly one bit (code $s$ is $s \oplus \lfloor s/2 \rfloor$, with $\oplus$ the bitwise exclusive or). Then, for each bit $b$:


  • a breakpoint whose every segment has bit $b = 1$ may carry weight only if $z_b = 1$;
  • a breakpoint whose every segment has bit $b = 0$ may carry weight only if $z_b = 0$;
  • a breakpoint whose two segments differ in bit $b$ (there is exactly one such bit, by the Gray code) is not limited by bit $b$.



with $L_b$ the breakpoints of the first kind and $R_b$ of the second, plus the weights' own rows from lesson The lambda (SOS2-style) formulation built from binaries. The program prints the codes and sets for 4 segments, then fixes each code and asks HiGHS which breakpoints may carry weight:



Take breakpoint 1: it ends segment 0 (code 00) and starts segment 1 (code 01). Both have bit 1 = 0, so breakpoint 1 is in $R_1$ and needs $z_1 = 0$; they differ in bit 0, so bit 0 leaves it free. Each of the four codes opens exactly one segment's two ends, which is the neighbour rule. With a plain binary count (00, 01, 10, 11) instead, segments 1 and 2 would differ in two bits, and their shared breakpoint would be limited by neither, so it could carry weight next to any segment.


When $K$ is not a power of 2, some codes name no segment; the rows then allow weight on no breakpoint, and since the weights must add up to 1, those codes are infeasible. The program checks every code for 2 to 9 segments:

All Three Forms Give the Same LP Bound Here


The LP bound of a MILP is the optimum of its LP relaxation, the same model with every integer variable relaxed to an interval (lesson Cutting planes: Gomory and cover cuts by hand); for a maximization it is an upper bound on the MILP, and the closer it is, the less the search has to do (lesson Aggregated vs. cumulative (disaggregated) forms compared two forms by it). The program writes the falling-tier credit line three ways, and also solves the relaxation of the weights-only rows of lesson The lambda (SOS2-style) formulation built from binaries, which is the loosest a curve can be while still passing through its breakpoints:



Same plan, same MILP optimum, and the same LP bound for all three, equal to the bound of the weights-only rows. Relaxed, the weights-only rows allow every convex combination of the breakpoints: the smallest convex region that contains the curve, its convex hull. No formulation that contains the curve can relax to anything smaller, so that bound is the best a formulation of the curve can give. Vielma calls a formulation whose LP relaxation reaches this best bound sharp (his Definition 2.2). He shows that the incremental form is locally ideal, a stronger property that implies sharpness (section 8, and Proposition 2.4); the table shows the lambda and log forms reaching the same bound on this curve. The project binaries still leave a gap, $26,959.1k against $26,753k, and no way of writing the curve can close it.


So on the LP bound, the formulations tie. What differs is their size, and how the search behaves.


Fewer Binaries Is Not Fewer Nodes


The medium portfolio, with each program's contractor billing its total list-price work on a curve whose rate falls evenly from 1.00 to 0.60 per $k across $K$ equal tiers. The three invoices must fit 80% of the capital budget. HiGHS solves each form to a zero gap and reports its branch-and-bound node count, the number of subproblems its search tree held (a node is one LP of branch and bound, lesson Branching on a fractional variable):



Every form reaches the same optimum, and all share one LP bound. The log form has by far the fewest binaries (12 against 48 at $K = 16$) and the fewest rows. But the search tells another story: the incremental form needed at most 7 nodes (0 means HiGHS closed the gap at the root, before branching), the log form hundreds to thousands, the lambda form thousands.


Why can the form with the most binaries be the quickest? Look at what one branch does. In the incremental form, $w_{k+1} \le \phi_{k+1} \le w_k$, so the binaries are ordered: branching on $w_k = 0$ forces every later $w$ to 0, and $w_k = 1$ forces every earlier one to 1. Either side of the branch settles a whole run of binaries. In the lambda form, $z_k = 1$ fixes all the others, but $z_k = 0$ removes only one segment of $K$. Vielma (section 8) explains the incremental form's fewer nodes in the same terms, citing computational studies.


Do not read the table as a law. Node counts depend on the instance, the solver and its version, even on the order the rows are written in, and these are three curves in one model on one portfolio. What the table does show is that the number of binaries does not predict the search: measure the formulations on your own instances before choosing, as lesson Aggregated vs. cumulative (disaggregated) forms did for precedence rows.

Summary


  • The incremental form fills segments in order, with a binary for each full one. $\phi_{k+1} \le w_k \le \phi_k$; $K - 1$ binaries; the same rows state any "next stage only after this one is complete" rule.
  • A Gray code picks a segment with about $\log_2 K$ binaries. Each bit limits the breakpoints whose segments agree on it; neighbours differ in one bit, so their shared breakpoint stays usable.
  • All three forms give the same LP bound here. Each reached the bound of the curve's convex hull, the best any formulation can give (sharp), so the choice between them is not about the bound.
  • Fewer binaries is not fewer nodes. On GridCap medium the incremental form needed at most 7 nodes, the log form up to 2,140 and the lambda form up to 6,432; measure on your own instances.

Design Note: Keep Every Formulation Behind One Signature


add_lambda, add_incremental and add_log take the same arguments and return the same Piece: the expressions for $x$ and $y$ and the binaries used. The model never knows which one built its curve, so forms_compared.py and medium_discounts.py switch formulations by passing a different function, and the tests check every form against the same points. When a new instance solves slowly, trying another formulation is then a one-word change, and the measurement is cheap enough to make before arguing about which form "should" be faster.
