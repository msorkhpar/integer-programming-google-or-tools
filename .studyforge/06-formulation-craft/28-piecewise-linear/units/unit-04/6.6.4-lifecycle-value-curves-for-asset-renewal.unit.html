  17. Lifecycle value curves

GridCap's asset team has a renewal fund of $3,000k for the small portfolio's ten assets that have a replacement project. Until now a replacement was all or nothing. The field crews point out that most of these assets can be renewed in part: replace a third of a line's spans, half of a pole set, the worst breakers of a bay. A partial renewal costs part of the replacement and buys part of its value. But not in proportion: renewing the first quarter of a worn-out line removes far more failures than the last quarter, and for some assets it is the other way round. The value of a renewal as a function of how much is renewed is a lifecycle value curve. This lesson builds one per asset from GridCap's failure model, puts all ten into one model with the cheapest exact formulation for each, and checks the result with two other tools, in six rules.

GridCap is a fictional utility's portfolio, generated for this course; the renewal fund and partial renewals are invented for this lesson.

A Lifecycle Value Curve Comes From the Asset's Failure Model

Every GridCap asset has a Weibull failure model with shape $\beta$ and scale $\eta$ (years), an age $a$ and a consequence of failure $\text{cof}$, the cost of one failure in $k (lesson Predictive vs. prescriptive: where PoF/RUL predictions stop and optimization starts). Assume that a failed asset is repaired just enough to run again, so that a failure does not make it any younger. Under that assumption the expected number of failures between ages $a$ and $a + h$ is the growth of the cumulative hazard $\Lambda(t) = (t/\eta)^\beta$ over those years:

with $h = 5$, the plan's five years. Now define a renewal of depth $d \in [0, 1]$: $d = 0$ is nothing, $d = 1$ a full replacement, and in between the asset becomes as old as $(1 - d)\,a$, the same convention as lesson Predictive vs. prescriptive: where PoF/RUL predictions stop and optimization starts's repairs, which took an asset back to half its age. It costs $d \times \text{capex}$ of the asset's replacement project. Its value is the failure cost it avoids over the plan:

$V$ is not piecewise linear; it is a smooth curve. To put it in a MILP, sample it at five depths, $0, 0.25, 0.5, 0.75, 1$, and join the samples by straight lines: a piecewise-linear curve with five breakpoints, which lessons Convex piecewise costs without binaries to Incremental and logarithmic formulations know how to write.

P019, a 28-year-old pole set, avoids $837k of failures if a quarter of it is renewed and $2,245k if all of it is, for a full price of $1,720k. P013 avoids $55k for $1,010k. The last column is the next rules' business.

Wearing-Out Assets Have Concave Curves, the Others Convex

Five curves are concave and five convex, and the column that sorts them is $\beta$: every asset with $\beta > 2$ has a concave curve, every one with $\beta < 2$ a convex one. That is not a coincidence of this portfolio; it follows from the formula.

The value is $\text{cof}\,(N(a) - N(u))$ with $u = (1 - d)\,a$, so it is concave in $d$ exactly when $N(u)$ is convex in $u$ ($u$ falls in a straight line as $d$ grows). Here $N(u) = \Lambda(u + 5) - \Lambda(u)$, and its second derivative is $\Lambda''(u + 5) - \Lambda''(u)$, with $\Lambda''(t) = \beta(\beta - 1)\,t^{\beta - 2} / \eta^{\beta}$. For $\beta > 2$, $t^{\beta - 2}$ grows with $t$, so $\Lambda''(u + 5) > \Lambda''(u)$ and $N$ is convex: the value is concave. For $1 < \beta < 2$, $t^{\beta - 2}$ shrinks, and the value is convex.

In words: a wearing-out asset ($\beta > 2$, failures speeding up with age) loses most of its risk in the first part of a renewal, because that part takes away the oldest, steepest years; each further quarter buys less. An asset whose failure rate grows only slowly ($\beta < 2$) gains little from a shallow renewal, and the value comes in a rush at the end, when the renewal reaches the youngest years, where its failure rate changes fastest.

The shape decides the formulation (lesson Convex piecewise costs without binaries): the model maximizes value, so it pushes each curve up. A concave curve pushed up is exact with segment variables and no binaries. A convex curve pushed up is not; it needs the exact forms of lessons The lambda (SOS2-style) formulation built from binaries and Incremental and logarithmic formulations.

Five Breakpoints Are an Approximation You Can Measure

The curve the model sees is the five-point one, not $V$. The last column of the table is the worst gap: the largest difference between $V$ and the five-point curve, over 400 depths between 0 and 1.

The straight line between two breakpoints lies below a concave curve and above a convex one. So the five-point curve underrates every concave asset a little between its breakpoints, and overrates every convex one. The gaps here are small next to the values (P019: $30.3k on a curve that reaches $2,245k), and they shrink with more breakpoints. For A019, P019's pole set:

Twice the segments, about a quarter of the gap: for a smooth curve, the gap of a straight chord grows with the square of the segment's width. More breakpoints cost more variables (and, for a convex curve, more binaries or bits), so choose the number from a tolerance, not by habit: the smallest count whose worst gap is below what the decision can feel.

    How many breakpoints a curve needs

    • measuring how far a piecewise-linear curve is from the smooth one it replaces

    Not startedPassed

Problem statement

An engineering team approximates smooth curves (pump efficiency, failure cost, value of a renewal) by piecewise-linear ones before they go into a MILP. They want a rule instead of a habit: use the fewest equally spaced breakpoints whose curve stays within a tolerance of the true one.

Write fewest_breakpoints(f, lo, hi, tol, max_n=65):

  • f is the true function on [lo, hi]. A curve with n breakpoints (n >= 2) puts them at lo + (hi - lo) * k / (n - 1) for k = 0, ..., n - 1, with the true values there, and joins neighbours by straight lines.
  • Its gap is the largest |f(x) - curve(x)| over the 1,001 evenly spaced points lo + (hi - lo) * i / 1000, i = 0, ..., 1000.
  • Return the smallest n from 2 to max_n whose gap is at most tol, or None if none is.

The tests use curves of different shapes, so make no assumption about where on a segment the gap is largest. About fifteen lines.

CP-SAT Reads a Curve as a Table When the Decision Is Integer


OR-Tools' CP-SAT solver works on integers and has no SOS2 or piecewise-linear constraint (lesson The lambda (SOS2-style) formulation built from binaries's program found no SOS method on its CpModel). It does have the element constraint, add_element(index, expressions, target), which says target == expressions[index] for an integer variable index. If renewals are only sold in quarters (a depth of 0, 1, 2, 3 or 4 quarters), the curve is just its five breakpoint values, a table to look up:




The program rounds the values to whole $k (CP-SAT needs integers) and solves the quarter-step problem in CP-SAT and, for comparison, in MathOpt with the incremental form and the depth tied to an integer number of quarters:



Both find the same plan. The table form is exact for any shape, because there is nothing between the breakpoints to get wrong; the price is that the decision may only take the table's values. When the business decides in steps (crews, spans, units), that is a feature; when the depth is truly continuous, the forms of lessons Convex piecewise costs without binaries to Incremental and logarithmic formulations keep it continuous.


A Second Tool Checks the Formulation


The formulations of this module are a few dozen lines of code, and a wrong row in them gives a model that solves, reports "optimal", and is wrong. An independent check is cheap: build the same model in another modeling tool that writes the formulation itself, and compare the optimum. Pyomo, which section 5 covers (lesson Piecewise functions and the IIS tools is about its piecewise functions), has a Piecewise component: given a variable $x$, a variable $y$, the breakpoints and the values, it adds the rows for $y = f(x)$. Its pw_repn argument names the formulation: "CC" is the lambda form with segment binaries, "INC" the incremental form, "LOG" the logarithmic one, and the default "SOS2" hands an SOS2 constraint to the solver; pw_constr_type="EQ" asks for $y = f(x)$ rather than one side.




The program solves it with HiGHS through Pyomo's appsi_highs interface, once per formulation, next to the MathOpt model with the incremental form on every curve:



Three formulations written by another tool's authors agree with this module's code, to the $0.1k and on the depths. The fourth shows the point of lesson The lambda (SOS2-style) formulation built from binaries from the other side: Pyomo's default SOS2 representation needs a solver interface that accepts SOS constraints, and its HiGHS interface refuses it. A check like this belongs in the model's tests, on a small instance, where it catches a broken formulation the day it is broken.

Problem statement


A water utility has a refurbishment fund for its fleet of pumps. Each pump in pumps has an age (years), a Weibull shape beta and scale eta (years), a cost per failure cof ($k) and the cost of a full refurbishment capex ($k). A refurbishment of depth d between 0 and 1 costs d * capex and leaves the pump as old as (1 - d) * age. A failed pump is repaired just enough to run again, so the expected number of failures between ages a and a + h is ((a + h) / eta) ** beta - (a / eta) ** beta.


  1. Write value_points(pump, horizon): the failure cost (in $k) that a refurbishment avoids over the next horizon years, at each depth of DEPTHS = (0, 0.25, 0.5, 0.75, 1), as a list of five numbers.
  2. Write plan(pumps, fund, horizon): a MathOpt model that chooses a depth per pump, with each pump's value read from the five-point curve through value_points (straight lines between them), keeps the total cost within fund, and maximizes the total value. Solve it with HiGHS to a zero gap and return the optimal value and a dict of depths.


With $R$ the pumps and $V_{i,j}$ pump $i$'s value at depth $D_j$, write the formulation first:



Some fleets have pumps whose failure rate speeds up with age, and some whose rate grows slowly. Look at the curves' shapes before you choose how to write each one; the cheapest exact choice per pump is the one a reviewer expects, but any exact formulation passes.


The tests compare your points with the formula, and your plan's value with a Pyomo model built from the same curves with pyomo.environ.Piecewise(..., pw_constr_type="EQ", pw_repn="INC") and solved by HiGHS. About thirty lines.

The Model


The renewal model on GridCap small's ten replacement candidates, with each curve written by its shape. This model is new in this lesson; everything in it is marked.


Sets. $R$ the candidates: the projects with a replacement intervention, each with its asset (10 on small); $R_A \subseteq R$ those whose value curve is concave, $R_B = R \setminus R_A$ the others (convex); $j = 0, \dots, 4$ the breakpoints and $k = 1, \dots, 4$ the segments.


Parameters. $\text{capex}_i$, the replacement project's cost ($k); $D_j = j/4$, the depths of the breakpoints; $V_{i,j} = V_i(D_j)$, asset $i$'s value at depth $D_j$ ($k, from its Weibull $\beta_i$, $\eta_i$, age $a_i$ and $\text{cof}_i$); $s_{i,k} = (V_{i,k} - V_{i,k-1}) / (D_k - D_{k-1})$, the slopes; $F = 3{,}000$, the fund ($k).

Summary


  • A lifecycle value curve comes from the asset's failure model. With minimal repair, a renewal of depth $d$ avoids $\text{cof}\,(N(a) - N((1-d)a))$ over the plan; sample it at five depths.
  • Wearing-out assets have concave curves, the others convex. $\beta > 2$ gives concave, $\beta < 2$ convex, from the sign of $\Lambda''(u + 5) - \Lambda''(u)$.
  • Five breakpoints are an approximation you can measure. Chords lie below a concave curve and above a convex one; doubling the segments cut P019's worst gap from $30.3k to $8.3k.
  • Each curve gets the cheapest exact form. Segments for the concave, incremental for the convex: the exact plan with 15 binaries instead of 30, worth $69.2k more than the all-segments plan.
  • CP-SAT reads a curve as a table when the decision is integer. With depths in quarters, add_element looks the value up, and CP-SAT and MathOpt find the same $2,813k plan.
  • A second tool checks the formulation. Pyomo's Piecewise (INC, CC, LOG) agrees with MathOpt to the $0.1k; its default SOS2 is refused by its HiGHS interface.

Design Note: Keep the True Curve Next to the Approximation


The model optimizes the five-point curves; the planners care about $V$. renewal_plan.py keeps both: it solves on the approximation and reports the plan's value on the true curve. That one extra line is what exposed the segment-only model ($2,971.0k claimed, $2,887.5k real) and what shows that nine breakpoints change the estimate more than the decision. A model whose input is an approximated curve should always report both numbers, and a review should ask for the gap between them.
