GridCap's engineers have sent the planning team four rules about the small portfolio, written the way engineers write them:

  • "P030 and P032 both need the same Valley line out of service. Fund one or the other, not both."
  • "Replacing the Ridge towers in P028 means P024 has to be built too, to carry the Ridge load."
  • "If P022 and P025 are both funded, the Valley yard is overloaded unless P033 rebuilds it."
  • "Undergrounding P034 needs one of the Plains replacements, P013 or P040."

Each sentence is logic: not both, if … then, if both … then, needs one of. A MILP has no logic operators, only linear rows over numbers. This lesson shows that with 0/1 variables every one of these sentences is a linear row, how to check that a row says what you mean, and when a piece of logic needs a variable of its own, in five rules.

GridCap is a fictional utility's portfolio, generated for this course; the four rules above are invented for this lesson.

NOT Is One Minus the Binary

Write $a$ for the statement "project $a$ is funded". Its binary $x_a$ is 1 when the statement is true and 0 when it is false, so the binary is the statement's truth value. That one fact is what makes logic linear.

The statement "project $a$ is not funded" is true exactly when $x_a = 0$. Its truth value is therefore

which is 1 when $x_a = 0$ and 0 when $x_a = 1$. It is a linear expression, so it can stand anywhere $x_a$ can. Every rule below that mentions "not" is written by putting $1 - x$ where the statement appears and then moving terms so the row reads cleanly.

An Implication Between Two Decisions Is One Inequality

"If $a$ then $b$", written $a \Rightarrow b$, forbids exactly one combination: $a$ true and $b$ false. Every other combination is allowed, including $a$ false and $b$ true (the rule says nothing about $b$ when $a$ is not funded). The row

forbids the same combination and nothing else. If $x_a = 1$, the row reads $1 \le x_b$, so $x_b$ must be 1. If $x_a = 0$, it reads $0 \le x_b$, which every value of $x_b$ satisfies. That is the parent rule of lesson Decisions, objectives and constraints: turning a planner's question into a model, $x_c \le x_{p(c)}$: "if the child is funded, the parent is".

So a rule phrased "$a$ needs $b$", or "$a$ only if $b$", is "if $a$ then $b$", and its row is $x_a \le x_b$: the project that needs the other goes on the small side of the row. Sources name the projects in different orders (MIT's 15.053 text, in Further reading, writes its contingent investment as $x_j \ge x_i$ because there $i$ is the one that needs $j$), so read the sides, not the letters.

Two more rules come out of it by substituting NOT:

  • "If $a$ then not $b$" (not both): $x_a \le 1 - x_b$, which is $x_a + x_b \le 1$.
  • "If not $a$ then $b$" (at least one of the two, the OR of $a$ and $b$ as a rule): $1 - x_a \le x_b$, which is $x_a + x_b \ge 1$.

A row says what you mean if it allows exactly the 0/1 combinations the logic allows. With two or three binaries there are only four or eight combinations, so you can check every one. The program below builds each row in a tiny model, fixes the binaries to each combination through their bounds, and asks HiGHS whether the model is feasible (the module's allowed_values helper); then it compares the combinations the row allows with those the logic allows:

Each allowed combination prints as its digits in the order ab (or abc), so 01 means $x_a = 0$ and $x_b = 1$:

a -> b allows every combination except 10, which is exactly the forbidden one.

The same row also says something you did not write. "If $a$ then $b$" is the same rule as "if not $b$ then not $a$" (its contrapositive), and $x_a \le x_b$ enforces both at once: with $x_b = 0$ the row reads $x_a \le 0$. So "P028 needs P024" also means "without P024, no P028", and a planner reading the solution should expect both.

CP-SAT, OR-Tools' constraint solver (lessons Integer and Boolean variables, linear constraints over integers to When CP-SAT beats MIP, and when it doesn't), does have logic operators. Its Boolean variables have negations (~x reads "not x"), and it takes implications and clauses as constraints of their own. The OR-Tools sample reified_sample_sat.py writes "if $b$ then $x$ and not $y$" three ways: an AND that applies only when $b$ is true, two implications, and two OR clauses. cpsat_logic.py enumerates every solution of each version and puts the two linear rows $b \le x$ and $b \le 1 - y$ (over 0/1 variables in MathOpt) beside them, checked with allowed_values:

All four allow the same five assignments, and only 110 has $b$ at 1. The logic form and the linear form state one rule. The difference is in who solves it: a MILP solver needs the linear rows, and CP-SAT accepts either.

AND or OR on Either Side of an Implication Is Still One Row

Real rules join more than two statements. Three shapes cover almost all of them:

  • "If $a$ and $b$, then $c$." $x_a + x_b - 1$ is 1 when both are funded and 0 or $-1$ otherwise, so the row $x_a + x_b - 1 \le x_c$ forces $x_c = 1$ only when both are funded.
  • "If $a$, then $b$ or $c$." $x_b + x_c$ is at least 1 when either is funded, so $x_a \le x_b + x_c$ forces one of them only when $a$ is funded.
  • "If $a$ or $b$, then $c$." This is two implications, $a \Rightarrow c$ and $b \Rightarrow c$, so two rows: $x_a \le x_c$ and $x_b \le x_c$.

The same truth-table check confirms all three. Its last rule is a classic slip, the implication written the wrong way round:

(a and b) -> c refuses only 110; a -> (b or c) refuses only 100. The reversed row allows 10 and refuses 01: it says "if $b$ then $a$", a different rule that the solver will enforce without complaint. Read against the rule it was meant to state, "$a$ needs $b$", the reversed row lets through the plan that funds $a$ without $b$ (10), which the rule forbids, and refuses the plan that funds $b$ alone (01), which the rule allows. No solver can catch a row written the wrong way round, because both directions are valid rows. A four- or eight-line truth table, or a test that fixes a plan the rule must refuse and checks that the model refuses it, does catch it.

"If $a$ or $b$, then $c$" can also be written as the single row $x_a + x_b \le 2\,x_c$. It allows the same 0/1 combinations, but its LP relaxation allows more fractional points: with $x_a = 1$, $x_b = 0$ it lets $x_c = 0.5$, which the two-row form refuses. Lesson The integrality gap, measured on GridCap showed that two correct formulations can have different LP bounds, and the one that admits fewer fractional points can never have the weaker bound; prefer the two rows.

Problem statement

A regional water utility is choosing next year's capital projects. Its engineers have handed the planners four kinds of rule, each given to you as data:

  • Supports (needs_any, a dict from a project to a list of projects). A project may be funded only if at least one of its supports is funded too. The treatment-plant expansion, for example, needs either the north main or the south main to carry its output.
  • Group triggers (all_trigger, a list of (group, consequence)). If every project in the group is funded, the consequence must be funded as well; if only some of them are, the rule asks nothing. A group may hold any number of projects.
  • Incompatible pairs (never_with, a list of (a, b)). The two projects may not both be funded.
  • Pairs (together, a list of (a, b)). Both are funded, or neither is.

AND, OR and XOR as Values Need a New Binary, Pinned From Both Sides


So far every piece of logic was a rule: a row that refuses plans. Sometimes the model needs the logic as a value instead, a number other rows and the objective can use. "The Valley region gets distribution work" is the OR of its distribution projects' binaries; a saving that applies "when both P030 and P032 are funded" needs the AND of two binaries. A value needs a variable: a new binary $z$, with rows that pin it to the logic.


For $z = a \text{ AND } b$, the rows are



The first two push $z$ down: if either project is not funded, $z$ must be 0. The third pushes $z$ up: if both are funded, $x_a + x_b - 1 = 1$ and $z$ must be 1. For $z = a \text{ OR } b$:



the first two push $z$ up when either is funded, and the last pushes it down when neither is. Both extend to any number of projects: an AND of $n$ binaries is $z \le x_i$ for each $i$ and $z \ge \sum_i x_i - (n - 1)$; an OR is $z \ge x_i$ for each $i$ and $z \le \sum_i x_i$.


XOR ("exactly one of the two") as a value takes four rows, two each way:



The program lists, for each combination of $x_a$ and $x_b$, the values of $z$ the rows allow: with all the rows, with only the rows that push $z$ down, and with only those that push it up:



With all the rows, every line has exactly one value of $z$, and it is the logic's value: $z$ is pinned. With one side only, $z$ is pinned on some lines and free on others. The "down" rows alone leave $z$ free to be 0 when the logic says 1; the "up" rows alone leave it free to be 1 when the logic says 0.


XOR as a rule is simpler than XOR as a value: "fund exactly one of $a$ and $b$" is the single row $x_a + x_b = 1$, with no new variable. Use the four rows only when the model needs the XOR's value somewhere else.


Pin Only the Side the Model Would Exploit, or Both When Unsure


A variable pinned from one side is not always a bug. The solver moves a free variable in whichever direction helps the objective, so a side matters only if the solver wants to move $z$ that way. The program one_side.py shows both cases on GridCap small with $y_r$, the OR of region $r$'s distribution projects ("region $r$ gets distribution work"):




First, a rule: the distribution engineering team can supervise work in at most 2 regions, so $\sum_r y_r \le 2$. Second, a reward: planners credit $150k of value for every region that gets distribution work, so the objective gains $150 \sum_r y_r$. Each is solved with both sides, with one side, and with the other:



  • In the rule, the solver wants $y$ small, because every $y_r$ at 1 uses up the limit of 2. So the "up" rows are the ones that matter: they force $y_r = 1$ wherever there is work. With them alone the answer is the same as with both. With the "down" rows alone, nothing forces $y_r$ up, so the solver may leave every $y_r$ at 0 and meet the limit on paper: the plan serves 3 regions and keeps its old value, $25,336k. The rule is silently gone.
  • In the reward, the solver wants $y$ large, because every $y_r$ at 1 adds $150k. So the "down" rows matter: they keep $y_r = 0$ where there is no work. With the "up" rows alone, the solver sets all four to 1 and claims $25,936k while the plan serves only 3 regions; its real value is $25,786k. The report would be wrong by $150k, and the plan is not even the best one, which is worth $25,833k.


So the side to keep is the one that resists the solver: when $y$ is pushed small (a $\le$ row or a cost), keep the rows that push it up; when $y$ is pushed large (a $\ge$ row or a reward), keep the rows that push it down. A dropped side saves rows but makes the model depend on how $y$ is used, and a later change (a reward added to a variable that was only capped) breaks it without a sound. When a variable is used in more than one way, or you are unsure, write both sides: the extra rows never cut off a correct plan.

Summary


  • NOT is one minus the binary. $1 - x_a$ is the truth value of "not $a$" and can stand wherever $x_a$ can.
  • An implication between two decisions is one inequality. $a \Rightarrow b$ is $x_a \le x_b$, which also enforces "not $b$ implies not $a$"; not both is $x_a + x_b \le 1$, at least one is $x_a + x_b \ge 1$.
  • AND or OR on either side of an implication is still one row. Check a row against its truth table; a reversed row is valid and wrong.
  • AND, OR and XOR as values need a new binary, pinned from both sides. Rows that push $z$ down and rows that push it up together leave exactly the logic's value.
  • Pin only the side the model would exploit, or both when unsure. A dropped side either deletes a rule silently or lets the solver claim value it does not deliver.

Design Note: Test a Logic Row on the Plans It Must Refuse


Every row in this lesson is short, and every one can be written backwards without any tool noticing: $x_a \ge x_b$ is as valid a row as $x_a \le x_b$. The cheapest protection is the one the truth-table program uses: fix a plan the rule must refuse, check the model refuses it, and fix a plan the rule must allow, check the model allows it. With two or three binaries that covers every case; on a real model, one allowed and one refused plan per rule catches the reversed row, the missing side and the wrong project id. Section 12 builds that into a test suite, and this module's practices are graded exactly that way.
