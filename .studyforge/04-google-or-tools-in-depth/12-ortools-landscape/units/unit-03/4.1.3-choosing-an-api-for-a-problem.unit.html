  16. Choosing an API

By the end of section 4, GridCap's planning service will use five parts of OR-Tools: MathOpt for the project selection, CP-SAT for the vegetation crews' schedule, the assignment solver for crews to sites, a minimum-cost flow for shipping spare transformers, and the routing library for inspection routes. Nobody picked those by taste. Each problem statement carried the facts that decide it, and this lesson turns those facts into a short procedure you can run on any statement, in an interview or on the job.

The procedure asks five questions in order, and each heading below is one of them. The evidence for each comes from a program. Some of it was measured in lessons What's in OR-Tools: MathOpt, CP-SAT, linear solver wrapper, routing, graph and Versions and the backends that ship with it; most of it is measured in lessons later in this section, which the page names as it goes, so read those as pointers to where the measurement is made, not to lessons you have already done. The one new program takes lesson What's in OR-Tools: MathOpt, CP-SAT, linear solver wrapper, routing, graph's crew assignment and adds two rules to it, one that the assignment solver can take and one that it cannot. GridCap is a fictional utility; its crews, sites and hours here are invented.

The Model

Lesson What's in OR-Tools: MathOpt, CP-SAT, linear solver wrapper, routing, graph's crew assignment, with the two new rules marked.

Sets. $K$ = {Ridge, Valley, Coast, Plains}, the crews; $S$ = {S1, S2, S3, S4}, the substations; $F \subseteq K \times S$, the pairs a crew is not cleared for (new: $F$ = {(Ridge, S2)}).

Parameters. $h_{k,s}$, the travel hours for crew $k$ to reach site $s$ (whole hours); $T = 9$, the hours the shared truck can give the Coast and Plains crews together (new).

Variables. $y_{k,s} \in \{0, 1\}$ for every $(k, s) \notin F$: 1 if crew $k$ goes to site $s$. A pair in $F$ gets no variable at all.

Does It Move Vehicles Between Places? Then the Routing Library

A problem whose decisions are routes (which vehicle visits which stops, in which order, starting and ending at a depot) goes to the routing library first, and stays there when rules pile on. The OR-Tools routing guide lists the variants it is built for: several vehicles, vehicle capacities, time windows at each stop, resource limits at the depot, and stops that may be dropped at a penalty. Each of those is a parameter or a "dimension" of the routing model (taught from lesson The routing model: index manager, transit callbacks and the TSP on, at the end of this section), not a new formulation.

The price, from lesson What's in OR-Tools: MathOpt, CP-SAT, linear solver wrapper, routing, graph: the routing library searches, and reports ROUTING_SUCCESS for a good route, not a proof of the best one. Accept that for routes: the routing library takes their rules as parameters of one model, where a MILP would need a variable for every arc and every vehicle and rows to keep each route in one piece. Do not stretch "routing" to everything with an order in it or a truck in it, though. The order of jobs on one machine or one crew has no travel between places as its decision, and goes to CP-SAT below. And a problem that decides only how much moves along each road, with no vehicle's sequence of stops in it, is a flow (the next question), even when trucks carry the loads. Crews that go from one circuit's job to the next are the first case when the statement gives job lengths and an order but no travel between circuits: the decision is each job's day, and the table below sends the vegetation crews' schedule across circuits to CP-SAT.

Is It Exactly an Assignment, a Flow or a Knapsack? Then Its Special Solver, Until One Rule Breaks the Shape

Lesson What's in OR-Tools: MathOpt, CP-SAT, linear solver wrapper, routing, graph showed the special-purpose solvers giving the general models' answers with less code. The assignment solver documentation adds that it can be faster than the MIP or CP-SAT solver on the problem it was built for. But each takes one shape, and only that shape. The program here puts two new rules on the crew assignment and asks both the assignment solver and CP-SAT. A pair a crew may not use is easy for the assignment solver: never add that arc. Its shape is a one-to-one pairing, the rows $\text{one\_site}_k$ and $\text{one\_crew}_s$ above: no worker gets two tasks and no task two workers, so jobs that one crew does in turn are not an assignment.

The truck rule ties two crews' hours together, so it is a row of the model, and only a general model has rows:

With the forbidden pair, both still agree (18 hours). The 18-hour plan gives Coast and Plains 4 + 6 = 10 hours, over the truck's 9, so the truck rule must change it, and CP-SAT finds the 19-hour plan that keeps it. The assignment solver has no way to be asked: its only inputs are arcs with costs, one pair at a time, and the truck rule is about two pairs at once.

That is the test for every special-purpose solver. Can each rule be said in that solver's own inputs? For the assignment solver, a rule about one (worker, task) pair can (drop or price the arc); a rule that couples pairs cannot. For a flow solver, capacities, costs, supplies and demands can; "this arc is used only if that one is" cannot. For the knapsack solver, more capacity rows can (lesson What's in OR-Tools: MathOpt, CP-SAT, linear solver wrapper, routing, graph); must-do items, alternatives and parent links cannot. One rule that cannot be said, and the problem is a general model; the next two questions say which kind.

Are There Fractional Amounts or Dual Prices? Then a General Model in MathOpt

A general model now goes to MathOpt or CP-SAT. Two facts send it to MathOpt, with HiGHS or SCIP as the solver, whatever else it has:

  • A continuous variable: tons, megawatts, dollars that may be fractional. CP-SAT has no continuous variable (lesson Integer and Boolean variables, linear constraints over integers), and handed one through MathOpt it rounds it and still reports OPTIMAL (lesson Switching solvers: HiGHS, SCIP, CP-SAT, GLOP, Gurobi, later in this section, measures 22,532 against the true 23,669.5). Rules of logic do not change this: MathOpt states "if this, then that" with indicator constraints or big-M rows. An indicator constraint is a row that must hold only when a chosen binary variable is 1 (lesson Indicator constraints, later in this section); a big-M row is an ordinary linear row with a large constant $M$ times a binary in it, so that the row is switched off when the binary is 0 (lesson Deriving big-M from bounds, in section 6).
  • Dual values: a shadow price for the budget, a reduced cost for a project. Only an LP has them, and among MathOpt's solvers only GLOP, PDLP and HiGHS return them (measured in lesson Switching solvers: HiGHS, SCIP, CP-SAT, GLOP, Gurobi, later in this section); CP-SAT returns none.

The OR-Tools MIP guide gives the same split from its side: for problems with both integer and continuous variables it recommends a MIP solver (it names SCIP), and for integer-only problems, CP-SAT. This course uses HiGHS as its default MIP solver and SCIP as the second opinion, both through MathOpt.

Are There Intervals, Sequences or Dense Logic Over Integers? Then CP-SAT

An integer-only general model goes to CP-SAT when it is mostly logic: tasks with start times and durations that may not overlap, crews shared over time, "this job before that one, or the other way round", many if-then rules. Lesson When CP-SAT beats MIP, and when it doesn't, later in this section, measures why: a sequencing model written for HiGHS with big-M disjunctions kept a bound of 0 after 10,000 nodes on 10 circuits, while CP-SAT proved every optimum in its limit. CP-SAT also has the vocabulary: interval variables, add_no_overlap and add_cumulative (lessons Interval variables and NoOverlap and Cumulative resources: crews and outage windows), which the OR-Tools job shop example uses, and which MathOpt does not have.

All of that requires whole numbers. Data with decimals is scaled first (lesson Objectives, integer scaling and solution callbacks); a quantity that is truly continuous sends the model back to the previous question.

Everything Else Starts in MathOpt, and pywraplp Is for Code You Inherit

What is left is a general integer model with no special shape, no continuous part and no dense logic: GridCap's project selection is the example. It is a capital budget that is not a knapsack: its must-do projects, alternatives and parent links are the rules the knapsack solver cannot take (question 2 and lesson What's in OR-Tools: MathOpt, CP-SAT, linear solver wrapper, routing, graph). Lesson When CP-SAT beats MIP, and when it doesn't, later in this section, finds that on a plain selection both HiGHS and CP-SAT prove the same optimum, and that on GridCap medium's large ten-year selection HiGHS ends closest to proven. Start it in MathOpt: the model stays solver-free, so trying CP-SAT on it later is one argument (lesson Switching solvers: HiGHS, SCIP, CP-SAT, GLOP, Gurobi), and that measurement, on your own instances, settles it.

Two APIs are left off the procedure on purpose:

  • The linear solver wrapper (pywraplp) does the same job as MathOpt with an older design: the solver is fixed when the model is created, and its LP solvers drop integer variables silently (lesson Versions and the backends that ship with it). New code goes to MathOpt; a pywraplp model you inherit is read, tested and migrated (lessons Reading pywraplp code and Migrating a pywraplp model to MathOpt). Migrated means moved to MathOpt, where the procedure starts every general model, not ported to a special solver or another API.
  • Gurobi is a backend, not an API, and in this course's runner neither OR-Tools API can load it (lesson Versions and the backends that ship with it). When a problem needs Gurobi, use gurobipy (section 5, from lesson Models, attributes and the matrix API).

The Procedure, in Order

The five questions, in the order to ask them. The first that says yes decides:

  1. Vehicles moving between places? The routing library.
  2. Exactly an assignment, a flow or a knapsack, with every rule in that solver's inputs? The assignment, flow or knapsack solver.
  3. A continuous amount, or dual prices wanted? MathOpt, with HiGHS or SCIP (GLOP or HiGHS for LP duals).
  4. Intervals, sequencing or dense logic, all integer? CP-SAT.
  5. Otherwise: MathOpt, measured against CP-SAT when it matters.

Summary


  • Routes go to the routing library, which takes capacities, time windows and droppable stops as parameters and returns good routes rather than proven ones.
  • A problem that is exactly an assignment, flow or knapsack goes to its special solver, until one rule cannot be said in that solver's inputs; the assignment solver took a forbidden pair, and could not take a rule coupling two crews.
  • Continuous amounts or dual prices send a general model to MathOpt, because CP-SAT rounds continuous variables and returns no duals.
  • Intervals, sequencing and dense logic over integers send it to CP-SAT.
  • Everything else starts in MathOpt; pywraplp is for code you inherit, and Gurobi goes through gurobipy.

Design Note: Name the Deciding Fact in the Code


When you choose an API, write down the fact that chose it, next to the code: "routing: crews drive between substations", "CP-SAT: crew jobs may not overlap". Requirements move, and the fact is what tells the next engineer whether the choice still holds. The day a planner adds "Coast and Plains share a truck" to the crew assignment, the comment "assignment solver: exactly an assignment, nothing else" says at once that the code must change, which is easier than finding out from a plan that breaks the new rule.
