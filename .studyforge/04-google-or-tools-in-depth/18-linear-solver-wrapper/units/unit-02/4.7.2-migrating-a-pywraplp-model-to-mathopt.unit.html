The inherited selection script of lesson Reading pywraplp code now has to join GridCap's MathOpt code base. The rest of the planning service builds MathOpt models and switches between HiGHS, SCIP and CP-SAT with one argument; this script builds its model inside a SCIP solver object and cannot. The team lead's condition for the port is simple: prove it gives the same answer.

A port is a rewrite in which nothing about the model may change. This lesson maps every pywraplp call to its MathOpt counterpart, ports the script, and then proves the port with a test, which on GridCap's medium portfolio turns up a difference that is not a bug. GridCap is a fictional utility's portfolio. Three rules, one per heading.

Every pywraplp Call Has a MathOpt Counterpart

The shape is the same: variables with bounds, rows from expressions, an objective with a sense. Two things moved. Watch the defaults when you port a variable. NumVar and IntVar take both bounds every time. MathOpt lets you leave them out, and a bound left out is infinite:

So a ported NumVar(0, infinity, ...) must keep its lb=0. Leave it out and the variable may go negative.

Statuses map almost one to one. pywraplp's OPTIMAL, FEASIBLE, INFEASIBLE and UNBOUNDED have reasons of the same names in mathopt.TerminationReason. MathOpt splits the rest more finely: INFEASIBLE_OR_UNBOUNDED, NO_SOLUTION_FOUND (a limit stopped the search before any solution), IMPRECISE, NUMERICAL_ERROR and OTHER_ERROR. Problem statement

A storm-response depot plans its crews with an old pywraplp script, legacy_plan(data) in staffing.py. The planning service is moving to MathOpt. Write mathopt_plan(data): the same model in MathOpt, solved by SCIP, returning what legacy_plan returns: ("OPTIMAL", cost, {variable name: value}), or (reason name, None, None) when the solve is not optimal (use result.termination.reason.name).

Read the legacy function first; it is the specification. Its model, with $K$ the crew kinds:

$n_k$ is the number of crews of kind $k$, each covering $h_k$ hours at cost $c_k$, between the union minimum $m_k$ and the most available $\bar n_k$; $o$ is overtime hours at rate $r$ per hour, at most $\bar o$; the depot needs between $L$ and $U$ hours covered. Keep the variable names the old script uses (crews_<kind>, overtime).

The tests run both functions on several depots and check that they agree on the status, the cost and the variables reported. About fifteen lines.

MathOpt Keeps the Model Apart From the Solver


Here is the port of the inherited script, block by block against lesson Reading pywraplp code's version:



  • BoolVar became add_binary_variable, with the same names, so that a row or a variable can be found by the name it had before.
  • The budget's RowConstraint(-infinity, B) plus a loop of SetCoefficient became one expression with <=. Its lower bound was $-\infty$, so nothing is lost. A ranged row would need add_linear_constraint(lb=..., ub=..., expr=...).
  • SetBounds(1, 1) on a binary became lower_bound = 1: a binary's upper bound is already 1.
  • The parent and alternative rows keep their names, parent_<id> and alt_<group>.


The solve moved out of the model:



quiet_solve is mathopt.solve with standard output pointed at /dev/null for the call, the course's way of keeping a stray line printed by the bundled HiGHS out of the output (it is in ported_selection.py).


This split is the reason to port. A pywraplp model lives inside one solver object, so trying it on SCIP, then CBC, then CP-SAT means three builds. A MathOpt model is built once and handed to each solver in turn:

A Port Is Proved by a Test: Same Value at Zero Gap, and Each Plan Allowed by the Other's Rules


What does "the same answer" mean? The obvious test compares the two optimal values. It needs two refinements.


First, two optimal plans can differ. When several plans tie for best, two correct models, or the same model on two solvers, may return different plans. So compare values, not plans. Then check each plan against the other model's rules. A port that dropped a row can reach a higher value with a plan the old model forbids, and this second check catches it even when a test instance happens to give equal values. This program checks the rules directly from the data:




Second, "optimal" has a tolerance. Lesson Best bound, incumbent, absolute and relative gap defined the relative MIP gap: a MIP solver stops and reports OPTIMAL once its plan is within that fraction of the best bound. Here are the old script and the port on three GridCap sizes, each first with its own default gap:






On medium, both report OPTIMAL and the values differ by $5k. Is the port wrong? No. pywraplp passes SCIP a relative gap of 0.0001 unless told otherwise, and $5 / 229{,}745 \approx 0.00002$ is inside it: $229,740k is "optimal" by that standard. The MathOpt port left relative_gap_tolerance at None. MathOpt's parameter documentation says the solver may stop at that gap only "when set", so unset, SCIP keeps its own default, and SCIP's parameter list gives limits/gap a default of 0: it stops only when the plan meets the bound. default_gap.py solves the port on medium with the gap unset and with pywraplp's 0.0001, and prints the bound beside the plan:




Unset, SCIP ran until bound and plan met at $229,745k; given 0.0001 through MathOpt, it stopped at pywraplp's $229,740k, with $18k still between plan and bound. So the $5k difference is the two gaps, not the port. Both plans keep every rule. With the gap set to 0 in both, they agree on value and plan.


So the test that proves a port, test_the_port_reaches_the_legacy_value_and_plan_at_zero_gap in the module's tests, does three things:


  1. Fix the gap at 0 in both, so that "optimal" means the same thing to both. Alternatively, compare the values within the larger of the two gaps.
  2. Compare values, and compare plans only where the optimum is known to be unique.
  3. Check each plan against the other's rules. The test also checks that both models have the same rows by name.


Run it on more than one instance. Tiny and small agree even at the default gap, so they would not have shown the gap issue; it took the medium portfolio.

Summary


  • Every pywraplp call has a MathOpt counterpart. Variables, rows and the objective map one to one. SCIP is SolverType.GSCIP, time limits become a timedelta, and bounds left out of add_variable are infinite. MathOpt raises where pywraplp answered 0.0.
  • MathOpt keeps the model apart from the solver. One model is built once and solved by HiGHS, SCIP and CP-SAT: all three found $25,336k on small.
  • A port is proved by a test. Fix the gap at 0 in both, compare values, and check each plan against the other's rules. At default gaps the medium portfolio gave $229,740k and $229,745k, both OPTIMAL and both correct.
