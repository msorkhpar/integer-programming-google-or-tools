  16. Simplex as walking between vertices

Lesson Solving a 2-variable LP by picture solved GridCap's budget split by listing every vertex of its region and keeping the best. That took ten pairs of lines for two variables; for a model with 100 variables and 200 rows the same count is about $4 \times 10^{81}$. GridCap's capital models are far bigger than that, and GLOP and HiGHS still solve their LPs. They do not list vertices. They start at one vertex and walk along the region's edges to a better neighbour, again and again, until no neighbour is better. That walk is the simplex method (George Dantzig, 1947), and it is the "S" in many solver logs.

This lesson builds the walk in about 60 lines of plain Python, runs it on the budget split, and watches it go A → B → C on the picture from lesson Solving a 2-variable LP by picture. It takes five rules.

The Model, With One Slack per Row

The budget split of lesson Solving a 2-variable LP by picture, unchanged: $d$ and $t$ are the money for distribution and transmission in $100k.

Simplex works with equations, not inequalities, so each $\le$ row gets a slack variable: a new variable that holds the row's unused amount (lesson Standard form, slack and surplus covers this conversion for every kind of row). The slack of budget, $s_\text{budget}$, is the money left unspent; $s_\text{crews}$ the crew-weeks left idle; $s_\text{ready\_t}$ the ready transmission work left undone. A slack can never be negative, since a negative slack would mean the row is broken:

The two models have the same plans: a plan $(d, t)$ satisfies the first exactly when the slacks it defines are all $\ge 0$ in the second. Now there are $n = 2$ original variables, $m = 3$ equations, and $n + m = 5$ variables in all.

A Vertex Is a Basis: Set n Variables to Zero and Solve for the Rest

Three equations can pin down three unknowns. So pick any 2 of the 5 variables, set them to 0, and solve the three equations for the other 3. The 3 you solve for are the basic variables, and the set of them is the basis; the 2 you set to zero are nonbasic. The point you get is a basic solution.

A slack at 0 means its row is tight, and $d = 0$ or $t = 0$ means a bound is tight. So setting 2 variables to zero is choosing 2 tight rows, which is exactly how lesson Solving a 2-variable LP by picture found the crossing points. Three bases, solved:

Nonbasic (set to 0)Basic, solvedPoint $(d, t)$Vertex?
$d, t$$s_\text{budget} = 30,\ s_\text{crews} = 72,\ s_\text{ready\_t} = 20$(0, 0)A
$t, s_\text{crews}$$d = 24,\ s_\text{budget} = 6,\ s_\text{ready\_t} = 20$(24, 0)B
$s_\text{budget}, s_\text{crews}$$d = 12,\ t = 18,\ s_\text{ready\_t} = 2$(12, 18)C

A basic solution whose values are all $\ge 0$ is a basic feasible solution, and the basic feasible solutions are exactly the vertices. A basic solution with a negative value is one of the crossings outside the region. Making $s_\text{budget}$ and $d$ nonbasic, for example, gives $t = 30$, $s_\text{crews} = 72 - 60 = 12$ and $s_\text{ready\_t} = 20 - 30 = -10$: the crossing at $(0, 30)$ that lesson Solving a 2-variable LP by picture found breaks ready_t.

Two vertices are neighbours, joined by an edge of the region, when their bases differ in one variable: A and B share the basic variables $s_\text{budget}$ and $s_\text{ready\_t}$, and differ only in whether $s_\text{crews}$ or $d$ is the third. One step of simplex swaps one variable into the basis and one out: the entering variable rises from 0, and the leaving variable falls to 0.

The Tableau Holds the Equations, and Its Last Row Says Which Variable Improves the Objective

A tableau is the equations written as a table of numbers: one row per equation, one column per variable, and a last column for the right-hand sides. Below them sits one more row for the objective. Write the objective's value as $z$, so $z = 5d + 4t$, and move every variable to the left: $z - 5d - 4t = 0$. The objective row stores the coefficients $-5, -4, 0, 0, 0$ and the current value of $z$ on the right.

Row $i$ is the row $i$ of $A$, then a 1 in the column of slack $i$ and 0 for the other slacks, then $b_i$. The last row is $-c$, zeros under the slacks, and 0 for $z$. Built for the budget split and printed:

Each basic variable's column is a unit column: a 1 in its own row and 0 everywhere else, including the objective row. That is what makes a tableau easy to read. Set the nonbasic variables to 0 and each row says "this basic variable equals the right-hand side". So the tableau is at vertex A: $d = t = 0$, the slacks hold 30, 72 and 20, and $z = 0$.

The objective row reads the same way. Written out, it says $z - 5d - 4t = 0$, that is $z = 0 + 5d + 4t$: raising nonbasic $d$ from 0 adds 5 to $z$ per unit, and raising $t$ adds 4. In general, the objective row always says

so a negative entry marks a variable that improves the objective if it enters. These entries are the reduced costs of the nonbasic variables (lesson Shadow prices, reduced costs and ranging from a solver reads them from a solver). Which negative entry to pick is a choice; the classic rule, Dantzig's rule, takes the most negative:

EPS is $10^{-9}$: an entry like $-10^{-15}$ is float noise, not a real improvement. Here the most negative entry is $-5$, so $d$ enters.

The Ratio Test Picks the Row That Leaves: the First Basic Variable to Reach Zero

$d$ rises from 0 while $t$ stays 0. Each equation then says how a basic variable must change to keep the equation true:

Every basic variable must stay $\ge 0$. $s_\text{budget}$ reaches 0 at $d = 30$, $s_\text{crews}$ at $d = 72/3 = 24$, and $s_\text{ready\_t}$ never does. So $d$ can rise to 24 and no further: one unit more and $s_\text{crews}$ would be negative, which means the plan would need more crew-weeks than exist. $s_\text{crews}$ is the leaving variable.

That is the ratio test: for every row whose entry in the entering column is positive, divide the right-hand side by that entry, and pick the row with the smallest ratio. A row whose entry is zero or negative sets no limit, because raising the entering variable leaves its basic variable unchanged or makes it larger. Ties go to the lowest row here; any tied row is a correct choice.

The smallest ratio is the step length: how far the entering variable rises. When no row has a positive entry, nothing stops the rise; lesson Infeasible, unbounded and degenerate LPs shows what that means. The walk program prints its test:

Taking the smallest ratio is what keeps the walk inside the region. Picking budget's 30 instead would push $d$ to 30, and the plan $(30, 0)$ needs 90 crew-weeks: it is the crossing that lesson Solving a 2-variable LP by picture found "outside: breaks crews".

Problem statement

A small simplex is being written for a water utility's pump-scheduling LP, and its first job is to decide each step: which variable enters the basis, and which row's basic variable leaves.

Write choose_pivot(T) in pivots.py. T is a tableau for $\max c \cdot x$ subject to $Ax \le b$, $x \ge 0$: one list per constraint row, each ending with its right-hand side, then a last row for the objective (its entries are the reduced costs, its last number the current value). Return the pivot as (r, k):

  • Entering column $k$: the column, among all but the last, with the most negative entry in the objective row (the lowest column index on a tie). If no entry is below $-10^{-9}$ (-EPS), the tableau is optimal: return None.
  • Leaving row $r$, by the ratio test over the constraint rows:

with the lowest row index on a tie.

You may assume that, whenever a column enters, at least one constraint row has a positive entry in it (lesson Infeasible, unbounded and degenerate LPs handles the case where none does).

The tableau must now describe vertex B, with $d$ basic in the row $s_\text{crews}$ held. That means turning $d$'s column into a unit column with its 1 in that row. The operation is a pivot, on the pivot element where the leaving row meets the entering column (here the 3). It uses the two row operations that never change what a system of equations means:


  1. Divide the pivot row by the pivot element, so the pivot element becomes 1.
  2. From every other row, objective row included, subtract the new pivot row times that row's entry in the pivot column, so the entry becomes 0.



pivot returns a new tableau and leaves the old one as it was. After the pivot:



Read it as before. $d = 24$, $s_\text{budget} = 6$ (that is $600k unspent), $s_\text{ready\_t} = 20$, and the nonbasic $t$ and $s_\text{crews}$ are 0. That is vertex B, worth 120, and the right-hand side of the objective row says so. The step moved along one edge of the region, from A to B, along the bottom edge $t = 0$.

When No Objective-Row Entry Is Negative, the Vertex Is Optimal


The objective row at B reads $z = 120 + \tfrac{2}{3} t - \tfrac{5}{3} s_\text{crews}$. Raising $t$ still pays $\tfrac{2}{3}$ per unit. That is less than the 4 that $t$ earned at A, because at B raising $t$ must lower $d$ to free crew-weeks: each unit of $t$ uses 2 crew-weeks, which costs $\tfrac{2}{3}$ of a unit of $d$, worth $\tfrac{10}{3}$, so the net is $4 - \tfrac{10}{3} = \tfrac{2}{3}$. The reduced cost counts that trade automatically. So $t$ enters, and the walk continues:



The budget runs out first, at $t = 18$. The tableau is now at vertex C: $d = 12$, $t = 18$, $s_\text{ready\_t} = 2$, value 132. Its objective row has no negative entry, and it says



That one line is a proof that C is optimal. It is an equation that every feasible plan satisfies, since the tableau is the original equations rearranged. Every feasible plan has $s_\text{budget} \ge 0$ and $s_\text{crews} \ge 0$, so every feasible plan has $z \le 132$, and C reaches 132. This is the optimality test: when no entry of the objective row is negative, no neighbour is better, and by the argument just given no plan anywhere is. Because the region is convex, a vertex that beats its neighbours is the best overall: an LP has no "local best" that is not the global best.


The two numbers in the slack columns also have a meaning the planner cares about. Leaving one unit ($100k) of budget unspent costs 2 risk points; leaving one crew-week idle costs 1. Lessons The dual LP and what its variables price and Shadow prices, reduced costs and ranging from a solver call them dual values (or shadow prices) and show what they say about buying more budget or crews.


Put together, the walk is a loop: find an entering column, run the ratio test, pivot, repeat until the optimality test passes.

Summary


  • A vertex is a basis. Add a slack to every row; set $n$ of the $n + m$ variables to zero and solve for the rest. If every value is $\ge 0$, the point is a vertex.
  • The tableau's last row says which variable improves the objective. A negative entry (reduced cost) marks a nonbasic variable whose increase raises $z$; Dantzig's rule picks the most negative.
  • The ratio test picks the row that leaves: the smallest $b_i / a_{ik}$ over rows with $a_{ik} > 0$, the first basic variable to reach zero. It keeps the walk inside the region.
  • A pivot rewrites the tableau so the entering variable is basic, with two row operations, and moves to a neighbouring vertex.
  • When no objective-row entry is negative, the vertex is optimal. The objective row is then a proof: $z$ equals the current value minus nonnegative terms.

Design Note: Why Real Solvers Do Not Store a Tableau


This tableau is dense: every pivot rewrites all $(m + 1)(n + m + 1)$ numbers, most of which are zeros in a real model (lesson Sparse model matrices and why solvers rely on sparsity). Production simplex codes keep the original sparse matrix and a factorization of the current basis instead, and compute only the one column and one row a pivot needs. That variant is called the revised simplex method. The walk is the same: same bases, same ratio test, same optimality test, and the 60 lines here are a faithful small model of it. GLOP, OR-Tools' simplex code, implements both the primal simplex of this lesson and the dual simplex that lesson Simplex, interior point and PDLP: GLOP, HiGHS, PDLP describes. Lesson Simplex, interior point and PDLP: GLOP, HiGHS, PDLP also compares simplex with methods that do not walk between vertices: interior point methods, which cross the inside of the region, and first-order methods such as PDLP, which take many small steps on the plan and the prices together.
