  15. Your first LP

GridCap's 2027 maintenance budget is $8,890k, and three programs want it: transmission, distribution and vegetation management (tree trimming). Last year the split was argued in a meeting: each program director asked for more, and finance cut everyone by the same share. This year the planning director wants a split she can defend: one that earns the most value, never books more crew work than the crews can do, keeps the regulator's minimum on tree trimming, and does not hand any single program more than half of what is spent. This lesson builds that split as a linear program and solves it. GridCap is the course's fictional utility; every number below is invented.

Lesson The problem zoo: LP, MILP, CP, NLP and how to pick met a linear program (LP) once: continuous variables, a linear objective, linear constraints. There, the LP was a stand-in for a yes/no model, and its fractions were a problem. Here the decisions really are amounts of money, so fractions are exactly right, and the LP is the model itself. Four rules, one per heading.

An LP Decides Amounts, So Each Variable Is a Continuous Quantity With Bounds

Start with the data. GridCap's small portfolio has 40 candidate projects across the three programs. Averaged over a program's projects, two rates describe it: how much NPV (net present value, lesson Decisions, objectives and constraints: turning a planner's question into a model: what a project is worth today, after paying for it) a $k spent on it returns (value per $), and how many crew-months each $1,000k of its work takes. Crews are the people who do the work, counted in crew-months (one crew working for one month). The portfolio says how many crew-months each program has in 2027.

Read one row: a $k on transmission returns $0.582k of NPV, and $1,000k of transmission work takes 2.46 crew-months. With 26 crew-months, transmission crews can do at most $26 \times 1000 / 2.46 = 10{,}569.1$ $k of work. Vegetation work is crew-heavy (6.41 crew-months per $1,000k), and with 2 crew-months its crews can do only $312.0k.

The decisions. The director controls one thing: how many $k each program gets. That is one decision variable per program, $s_k$, the amount spent on program $k$ in 2027, in $k.

The domain. A variable's domain is the set of values it may take. Money can be split to the dollar, so $s_k$ is continuous: any real number, not only whole numbers. Money spent cannot be negative, so $s_k \ge 0$. That $0$ is the variable's lower bound. It has no upper bound of its own: the rules below limit it.

add_variable(lb=0) is $s_k \ge 0$: with no ub the upper bound is $+\infty$, and with no is_integer=True the variable is continuous. Forget lb=0 and the default lower bound is $-\infty$ (lesson Standard form, slack and surplus prints a variable created with no bounds), which would let the model "spend" a negative amount on one program to free money for another. Always state the domain.

The objective. The director wants the most value. If each $k on program $k$ returns $v_k$, the split's value is

This line hides the main assumption of every LP. The value of program $k$ is proportional to its spend: the 4,000th $k returns as much as the first. And the programs' values simply add up: spending on one does not change what another returns. Those two properties, proportionality and additivity, are what "linear" means. Together with divisibility (a variable may take any fraction) and certainty (every number is known), they are the four assumptions an LP makes about the world. When one fails badly, as with the diminishing returns of lesson The problem zoo: LP, MILP, CP, NLP and how to pick's square-root curve, the LP is the wrong model, or needs the piecewise trick of section 6.6.

Every Rule Is One Linear Row, and a Ratio Is Multiplied Out Before It Is Written

A constraint, also called a row (each one is a row of the model's table of coefficients, lesson Standard form, slack and surplus), says which splits are allowed. In an LP, every constraint is a linear expression (numbers times variables, added) compared with a number by $\le$, $\ge$ or $=$. The director's four rules become four kinds of row.

Budget. The programs together get at most $B = 8{,}890$: $s_{\text{transmission}} + s_{\text{distribution}} + s_{\text{vegetation}} \le B$. It is $\le$, not $=$: nothing says the money must all be spent, and the solve below shows that the best split does not spend it all.

Crews. Program $k$'s work needs $m_k / 1000$ crew-months per $k, and it has $C_k$ crew-months: $(m_k / 1000)\, s_k \le C_k$, one row per program.

Floor. The regulator requires at least $300k of tree trimming: $s_{\text{vegetation}} \ge 300$.

Each row has a name, its label in the formulation. When a model misbehaves, you search for rows by these names.

Share. "No program gets more than half of what is spent" is a ratio:

A ratio of variables is not linear: it divides by a variable. MathOpt refuses it outright:

The fix is algebra. The total spend is never negative, so multiplying both sides by it keeps the direction of $\le$, and the row becomes linear:

The second line is how MathOpt keeps the row: it moved every variable to the left-hand side ($s_T - 0.5 s_T - 0.5 s_D - 0.5 s_V \le 0$) and records the row as a lower bound ($-\infty$, none) and an upper bound ($0$) on that expression. Lesson Standard form, slack and surplus uses this shape.

One caution about multiplying out. It is safe here because the total is never negative. If the denominator could be zero, the ratio rule says nothing (there is no ratio), while the multiplied row says $s_k \le 0$, which happens to agree. If the denominator could be negative, multiplying would flip $\le$ to $\ge$, and the row would be wrong. Check the sign of what you multiply by.

Problem statement

A city transit agency splits its maintenance budget across its modes: bus, rail and ferry. The council has passed two kinds of rule, both written as ratios:

  • no mode gets more than a share max_share of the total spent;
  • for each pair (a, b, ratio) in pairs, mode a gets at least ratio times what mode b gets (the council wrote it as "a / b must be at least ratio").

With $K$ the modes, $x_k \ge 0$ the amount spent on mode $k$, $\alpha$ the largest share and $P$ the pairs, the rules are:

Neither is linear as written. Multiply each one out first (every amount is $\ge 0$), then write add_share_rules(model, spend, max_share, pairs) in rules.py: it adds one row per mode and one row per pair to model, where spend maps each mode to its variable. Name the rows share_<mode> and ratio_<a>_<b>.

The tests fix every amount to a plan's value and ask GLOP whether your rows allow it, so any correct linear form passes. About five lines.

Read the rows. Three are full: the activity equals the bound. Distribution and vegetation have used every crew-month, and transmission sits exactly at half of the spend ($4{,}329.9 = 4{,}017.9 + 312.0$, so its share row's activity is $0$). The other rows have room: the budget has $8{,}890 - 8{,}659.7 = 230.3$ $k left, transmission's crews have $15.3$ crew-months idle, and vegetation got $12$ $k above its floor.


Now explain the answer from the rows, which is the skill this section is about.


  • Vegetation gets its crew limit, $312.0k. It returns 0.561 per $, and its crews allow no more.
  • Distribution gets its crew limit too, although it returns the least, 0.477. Why fund the worst program to the hilt? Because of the share rule: transmission may only match what the other two get together. Every $k given to distribution lets transmission take one more $k, so a $k to distribution really buys $0.477 + 0.582$ of value for $2k. The LP found that without being told.
  • Transmission gets exactly what the share rule allows, $4{,}017.9 + 312.0 = 4{,}329.9$.
  • So $230.3k of budget is left. No program can absorb it: two are out of crews, and the third is at its share. The best split leaves money unspent, which is why the budget row is $\le$. Written as $=$, it would force the plan to spend money that no rule lets it spend: the model would be infeasible, meaning no split satisfies every row.


The amounts are fractions of a $k (4,017.9, not 4,018). For money that is fine: the model's domain says any real number. For crews, trucks or whole projects it would not be, and that is where section 3's integer variables come in.

Problem statement


A port authority splits its maintenance budget across its terminals. Each terminal returns a value per $k spent, its work needs dock-crew hours per $k, it has a number of crew hours available, and some terminals have a floor the harbor board requires them to get. The authority wants the best split and, just as much, an answer it can read: did the solve succeed, what does each terminal get, and which limits decided it.


With $T$ the terminals, $v_t$ the value per $k, $h_t$ the crew hours per $k, $H_t$ the hours available, $f_t$ the floor and $B$ the budget:

A Changed Number Moves the Answer Only Through the Rows That Are Full


A planner's next question is always "what if?". Suppose GridCap can hire 3 more crew-months of distribution work, 12 instead of 9. Re-solve, and list the full rows, the rows whose activity sits on their bound:




The comparison uses a tolerance of $10^{-6}$, not ==: a solver works in floating point, and an activity of 8,889.9999999 is on its bound for every practical purpose.



The NPV rises by $4{,}733.5 - 4{,}611.5 = 122.0$ $k. Distribution's crews no longer stop it, and a new row is full instead: the budget. Distribution grows only until the money runs out, at 4,133.0, with crew-months to spare. Transmission still sits at half the spend, $8{,}890 / 2 = 4{,}445$.


This is the pattern of every LP answer. The solution is pressed against a few full rows; they decide it, and the rows with room do not. Change the number in a row with room, and nothing moves until the room is used up. Change the number in a full row, and the answer moves, until another row fills. Lesson Standard form, slack and surplus gives the room a name (slack), and lesson The dual LP and what its variables price puts a price on each full row (its dual value: how much the objective rises per unit of the row's bound).


The Model


Sets. $K = \{\text{transmission}, \text{distribution}, \text{vegetation}\}$, the programs.


Parameters. $v_k$, the NPV returned per $k spent on program $k$ ($k per $k); $m_k$, the crew-months program $k$'s work takes per $1,000k; $C_k$, the crew-months program $k$ has in the year; $B$, the year's budget ($k); $f$, the regulator's floor on vegetation spend ($k); $\alpha$, the largest share of the spend one program may get ($\alpha = 0.5$). For 2027: the table in the first section, $B = 8{,}890$, $f = 300$.


Variables. $s_k \ge 0$ for every $k \in K$, continuous: the $k spent on program $k$.


Objective.



Constraints.



The labels are the row names in the code: budget, crew_transmission, floor_vegetation, share_distribution, and so on.


Summary


  • An LP decides amounts, so each variable is continuous with bounds. State the domain every time: lb=0 for money, or the default $-\infty$ lets money flow backwards. Linear means proportional and additive; an LP also assumes divisibility and known data.
  • Every rule is one linear row; a ratio is multiplied out first. MathOpt refuses a division by a variable. Multiplying by a total that is never negative keeps the direction of the inequality.
  • Read the status, then the amounts, then the rows. A row's activity against its bound tells you which rules decided the answer, and lets you explain it in the planner's words.
  • A changed number moves the answer only through full rows. Rows with room do not matter until their room is gone.

Design Note: Averages Make the Model Linear, and Hide the Projects


The value of a program is not really 0.582 per $: its projects differ, and funding half of a transmission line returns nothing. The split model trades that detail for a model that is small, fast and easy to explain, which is the right trade for a budget-level question ("how much per program?"). The project-level question ("which projects?") needs yes/no variables and is section 3's model. Many utilities run both: the split sets each program's envelope, and the project model fills it.
