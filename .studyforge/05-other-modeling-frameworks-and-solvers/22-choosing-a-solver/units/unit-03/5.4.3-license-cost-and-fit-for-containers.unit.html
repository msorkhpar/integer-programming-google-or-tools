GridCap's planning service will run as a container job on AWS Batch on Fargate (lesson AWS Batch on Fargate, Step Functions and Lambda: who does what), inside a private network with no route to the internet: every night a job starts, reads a portfolio snapshot, solves, writes the plan and stops. Two people now have questions about the solver. Finance asks what it costs, this year and when the portfolio grows. Operations asks what the container needs for the solver to run at all: how big the image gets, and whether the solver must reach a license server before it will solve. GridCap is a fictional utility.

This lesson answers both for the seven solvers of lesson The landscape: Gurobi, CPLEX, Xpress, HiGHS, SCIP, CBC, CP-SAT, from two kinds of evidence: what the runner image itself says about the packages it holds, and what each vendor publishes. Vendor terms and prices change, so every one of them is quoted with the date of the page it came from, and a recommendation that uses them carries the date too. Lesson Licenses: size-limited, academic, and cloud/container (WLS) sets up Gurobi's licenses in detail; this lesson compares the routes across vendors and asks which fit a container.

Open-Source Solvers Cost Nothing to License, and Their Licenses Still Have Terms

footprint.py reads each solver package's own metadata in the runner image, the record pip saw when it installed the package, and adds up the size of its installed files:

What it means for the service:

  • One wheel brings four MILP solvers. OR-Tools (82.0 MB) carries HiGHS, SCIP, CBC and CP-SAT (lesson Versions and the backends that ship with it lists the bundled versions), under its Apache 2.0 license. The service that already installs OR-Tools for MathOpt pays nothing more, in money or image size, to have a second solver.
  • The licenses are permissive. Apache 2.0 (OR-Tools, and SCIP from 8.0.3), MIT (HiGHS, PuLP) and EPL 2.0 (CBC, from its README) all allow use inside a closed commercial service. Their terms are about notices and redistribution, not fees. One trap: SCIP releases up to 8.0.2 were under the ZIB Academic License, so an old pin of SCIP in a commercial service is a licensing question, not only a version question.
  • Packages carry more than you use. PuLP's 36.7 MB holds a CBC executable for each platform it supports (Windows, Linux, macOS, ARM), though a Linux container runs one. If image size matters, measure it this way rather than guess.
  • No network, no license server. The runner is started with docker run --network none (scripts/runner.py), and every open-source solver of this module solved there. That is the container fit a private-network batch job needs.

The money is not zero, though. A solver you do not pay for is one you support yourself: this course met several upstream bugs in OR-Tools' solver adapters, each found by a program and worked around in a lesson: errors whose reason is lost (lessons Simplex, interior point and PDLP: GLOP, HiGHS, PDLP and Common vs. solver-specific parameters, and what each solver rejects), HiGHS ignoring callbacks (lesson Callbacks and compute_infeasible_subsystem), and a crash on a cutoff limit (lesson Common vs. solver-specific parameters, and what each solver rejects). Budget engineering time for that, not license fees.

Free Commercial Tiers Stop at a Size GridCap Outgrows

Each commercial vendor has a free tier, and each is capped by model size. The caps, as published on the pages opened on 2026-11-11:

  • Gurobi, the license that comes with pip install gurobipy: up to 2,000 variables and 2,000 linear constraints, and 200 variables when the model has quadratic terms (Gurobi support article). The gurobipy PyPI page also calls the bundled license an evaluation license for non-production use.
  • CPLEX Community Edition: up to 1,000 variables and 1,000 constraints (IBM's pricing page).
  • Xpress Community License: rows plus columns at most 5,000 for linear and mixed-integer models, 200 for quadratic and general nonlinear ones, renewed yearly (FICO's license options page).

model_sizes.py counts GridCap's two model families at every size, the selection model of lesson The landscape: Gurobi, CPLEX, Xpress, HiGHS, SCIP, CBC, CP-SAT built in MathOpt, and the start-year (timing) model of lesson Cash-flow spreading across years counted from its formulation, and checks each against the three caps:

Everything up to GridCap medium fits every free tier; GridCap large, the 10,000-project portfolio, fits none, in either model. The timing model of the medium portfolio, 887 variables and 469 rows, already uses most of CPLEX's 1,000 variables. So a free tier is enough to put a commercial solver into the benchmark of lesson Honest benchmarking: instance sets, seeds, time-to-gap, shifted geometric mean on small and medium instances (and the evaluation licenses of the next section lift the cap for a trial), but not to run the service on the portfolio GridCap is growing into. The real price question is the paid license.

    Does the model fit the free tier?

    • each free commercial tier caps model size in its own way

    Not startedPassed

Problem statement

A team at a gas network wants to try commercial solvers on their free tiers before asking for quotes, and needs to know which of its models each free tier accepts. Free tiers cap model size in different ways: some cap variables and constraints separately, some cap their sum, and some have tighter caps when the model has quadratic terms.

A tier is described as {"linear": caps, "quadratic": caps}, where caps is a tuple (max_vars, max_rows, max_sum), and any of the three may be None, meaning that count is not capped. A model fits when its variables are at most max_vars, its rows at most max_rows, and variables plus rows at most max_sum, using the "quadratic" caps when the model has quadratic terms and the "linear" caps otherwise.

Write fits(n_vars, n_rows, quadratic, tier) in tiers.py. About five lines.

Three consequences for a recommendation:


  1. The only list price is for development, not for the service. CPLEX's $320.00 per user per month (the page also advertised a temporary discount) covers a developer, not a nightly production job; every vendor prices deployment by quote. So a cost comparison that a team can act on needs quotes, requested for the same deployment shape (one container job, how many threads, how many solves a night).
  2. Evaluation licenses make the benchmark free. Gurobi offers a free full-featured trial (30 days for commercial users) and free academic licenses; FICO an evaluation license with no size limit; so the harness of lesson Honest benchmarking: instance sets, seeds, time-to-gap, shifted geometric mean can run a commercial solver on GridCap large before anyone buys anything.
  3. Every figure carries its date. Write "as of the page opened on 2026-11-11" next to each price and term, in the recommendation itself. A reader a year later then knows to check, rather than trusting a number that has moved.


In a Container, a Commercial License Needs a Route Out


A popular claim, which lesson Licenses: size-limited, academic, and cloud/container (WLS) also corrects: "run the solver on AWS Batch on Fargate and the license problem goes away, because the containers are stateless". It does not. A container is a fresh machine every time it starts, which is exactly what a license tied to one machine cannot accept. Gurobi's container pages (its Docker image documentation and its docker-python README, opened 2026-11-11) list the routes that do work in a container:

token server (floating license)a license file with connection settings, mounted read-only at run time, and a network path to the token server, which runs outside the container clusteronly if the server is inside the network

The same pages say that NODE and Academic licenses do not work in containers, and that a license file should never be baked into the image: mount it at run time, or keep it as a Kubernetes secret. FICO's Xpress container image ships a time-limited community license for small problems, and its page says web floating licenses can be attached to a running container: the same pattern, a license service the container must reach. Outside its image, the xpress Python package uses the community license unless the environment variable XPRESS names the folder (not the file) that holds a license file, xpauth.xpr, as its PyPI page explains.


So for GridCap's job, in a private network with no internet, a commercial solver means one of two changes to the architecture: open an outbound route to the vendor's license service, or run a token server inside the network and pay for its upkeep. Either is a cost the license price does not show, and it belongs in the recommendation.

Problem statement


A team runs FICO Xpress from Python (pip install xpress) inside a container. The package's own page says how it finds a license: with no setting, it recognizes the free community license by itself; for a full license, you put the xpauth.xpr file in a folder and set the environment variable XPRESS to that folder's path, not the file's. The team wants its service to log, at start-up, which license it will get, so that a forgotten mount shows up in the first line of the log instead of as a size-limit error hours later.


Write xpress_license(env, files) in xproute.py. env is the container's environment, and files the set of file paths present in the container. Return:


  • "community license" when XPRESS is missing or empty;

Summary


  • Open-source solvers cost nothing to license, and their licenses still have terms. OR-Tools (Apache 2.0, 82.0 MB) brings HiGHS, SCIP, CBC and CP-SAT; SCIP before 8.0.3 was academic-only. The real cost is supporting them yourself.
  • Free commercial tiers stop at a size GridCap outgrows. Gurobi pip 2,000 × 2,000, CPLEX Community 1,000 × 1,000, Xpress Community 5,000 rows plus columns (pages opened 2026-11-11): medium fits all three, large fits none.
  • Commercial prices are quotes, so a recommendation dates every figure. The one list price, CPLEX's $320.00 per user per month, is for development only.
  • In a container, a commercial license needs a route out: WLS needs the internet, a token server needs a server; NODE and Academic licenses do not work in containers, and no license file goes into an image.

Design Note: Put the License Route in the Architecture Diagram


A commercial solver in a container is not a library choice; it is a network dependency (a license service or a token server), a secret to manage, and a failure mode at start-up. Draw it in the architecture next to the database and the object store, with who owns it and what happens when it is unreachable. If the answer is "the nightly job fails", the recommendation has to price that risk as well as the license.
