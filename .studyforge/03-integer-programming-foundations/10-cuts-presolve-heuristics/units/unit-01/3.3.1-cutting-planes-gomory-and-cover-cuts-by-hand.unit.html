GridCap's planners have watched HiGHS solve their selection models in under a second, and they have seen its log print a column called Cuts with numbers like 906 in it. A reviewer asks the obvious question: what is the solver cutting, and why does it help? This lesson answers it by doing the cutting by hand, on the smallest GridCap portfolio first and then on a two-variable model where every number fits on a line. GridCap is a fictional utility; its numbers are teaching data.

Lessons Yes/no decisions, and why rounding an LP fails and Bounds, incumbents and pruning use the words below too. They are defined again here, so this lesson can be read on its own.

The Model

The budget knapsack: fund each project or not, under one budget, for the most value. It is the one-period selection model of section 1 with every rule except the budget left out, so the cuts of this lesson have one row to work on.

Sets. $P$ the candidate projects.

Parameters. $v_i$, the value (NPV at the earliest start) of project $i$, in $k; $c_i$, its total cost (capex), in $k; $B$, the capital budget, in $k.

Variables. $x_i \in \{0, 1\}$ for every $i \in P$: 1 if project $i$ is funded.

Objective and constraint.

The LP Relaxation Overestimates, and a Cut Removes Its Optimum Without Removing Any Plan

The LP relaxation of a model with integer variables is the same model with the integrality dropped: here, $x_i \in \{0, 1\}$ becomes $0 \le x_i \le 1$. It is an LP, so it solves fast (section 2), and for a maximization its optimum is an upper bound on what any plan can reach (lesson The integrality gap, measured on GridCap gives the argument). On GridCap tiny:

The LP funds the projects with the most value per $k first: P007, P004, P001, and then 99% of P006, because only $1,950k of the budget is left and P006 costs $1,970k. Its value, 5,005.3, is 129.3 above the best real plan. That difference is the integrality gap of this instance (lesson The integrality gap, measured on GridCap measures it across GridCap).

A branch-and-bound solver (lessons Branching on a fractional variable to A knapsack branch-and-bound in 116 lines) uses the LP bound to throw away whole families of plans: if a part of the search can reach at most 4,900 and a plan worth 4,950 is already known, that part is never explored. The closer the bound is to the true best value, the more it throws away. There are two ways to bring the bound down: split the problem into cases (branching, lessons Branching on a fractional variable to A knapsack branch-and-bound in 116 lines), or add rows that the LP must also satisfy. The second is this lesson.

A valid inequality is a linear row that every 0-1 plan of the model satisfies. Adding one changes no plan's feasibility, so the integer optimum stays the same. A cut (or cutting plane) is a valid inequality that the current LP optimum breaks: adding it removes that fractional point, so the LP must move to another point, whose value is no higher. Finding a cut for a given LP point is called separation: the cut separates the point from the plans.

Two things decide whether a cut is any good: it must be valid (or the solver can lose the optimum), and it must be broken by the current LP point (or it changes nothing now). The rest of this lesson builds two kinds of cut that satisfy both, by construction.

A Cover Is a Set of Projects That Cannot All Be Funded

Take any set $C$ of projects whose costs add up to more than the budget:

Such a set is a cover (it "covers" more than the budget). No plan can fund every project in it. So every 0-1 plan funds at most $|C| - 1$ of them:

This holds for every 0-1 plan, so it is valid. It says nothing about money: it only counts projects. That is why it can cut fractional points the budget row allows.

On tiny, P001, P004, P006 and P007 cost 2,150 + 3,000 + 1,970 + 290 = 7,410, which is more than 7,390. They form a cover, and the cover inequality says at most 3 of the 4 are funded. The LP point funds 3.9898 of them:

The violation is how far the point is on the wrong side: $\sum_{i \in C} x_i - (|C| - 1)$. Positive means the point breaks the inequality, so it is a cut.

A cover is minimal when dropping any one of its projects leaves a set that fits in the budget. Minimal covers give the strongest cover inequalities. Add P005 to the cover above and it is still a cover (it costs even more), but no longer minimal, since without P005 it is still a cover. Its inequality allows 4 of 5, and the LP point satisfies it:

In general a non-minimal cover inequality is the minimal one with an extra variable on the left and 1 more on the right. Any point that satisfies the minimal one satisfies the longer one too, but not the other way round, so the longer one cuts less.

Separation Finds a Cover the LP Point Breaks

A planner does not pick covers by hand on a 400-project portfolio. The solver needs a rule that, given the LP point $x^*$, finds a cover whose inequality $x^*$ breaks. Rewrite the violation:

(subtract both sides from $|C|$). Each project in the cover "costs" $1 - x^*_i$, how far the LP is from funding it fully, and the cover is violated when those costs add up to less than 1. Projects the LP funds fully cost nothing; a project at 0 costs a full 1, so a violated cover never contains one. So separation asks: find a set whose weights exceed $B$, while keeping $\sum (1 - x^*_i)$ below 1.

That is itself a knapsack problem, so solvers solve it approximately. A greedy rule works well: take projects in order of $(1 - x^*_i) / c_i$, cheapest violation per $k of weight first, until the set covers the budget; then make it minimal by dropping projects, the worst ones first, while it stays a cover; and keep it only if it is violated.

On tiny it takes P001, P004 and P007 (each at 1, so they cost 0), then P006 (cost 0.0102), and the set now weighs 7,410: a cover, already minimal, with violation 0.9898. The same four projects found by hand:

A greedy rule can miss a violated cover that exists. When it returns None, that means "this rule found none", not "there is none". Exact separation is a knapsack problem of its own, and solving one exactly for every LP point would cost more than the cut is worth.

Each Round of Cuts Lowers the Bound, and the Gain Tails Off


One cut is one step. Repeat it: solve the LP, separate, add the cut, solve again, until the separation finds nothing. Each new LP has every cut so far.



lp_with_cuts builds the LP relaxation with one row $\sum_{i \in C} x_i \le |C| - 1$ per cut and solves it with GLOP. The share of the gap closed after a round is $(\text{first bound} - \text{bound}) / (\text{first bound} - \text{integer optimum})$. On tiny and on small (40 projects):



Read the tiny run line by line. The first cut removes the point with P006 at 0.99. The new LP optimum funds a sliver of P002 instead, at 0.007, and the bound falls by 122.9: most of the gap. The second cut, on P004, P006 and P002 (7,700 together), closes a little more. Then the LP point has P008 at 0.034 and the greedy separation finds no violated cover. The bound is 4,880.7, still above 4,876: covers alone did not close the gap.


On small, the pattern that matters shows: every round lowers the bound (it never rises, since each LP has one row more than the one before), but by less and less, and after 12 rounds 31% of the gap is closed. This is called tailing off, and it is typical of cutting planes. The LP point moves a little, a new fractional variable appears, and the next cut removes only that little piece.


That is why no modern solver relies on cuts alone. It cuts at the root of the search tree (the first node, before any branching) while the bound falls fast, then branches, and may cut again inside the tree. Branch-and-bound plus cutting planes is called branch-and-cut. HiGHS and SCIP both run it: the HiGHS log that lesson Reading a full MIP log line by line reads counts its cuts in a column of their own.


A Gomory Cut Comes From Any Tableau Row With a Fractional Right-Hand Side

Ralph Gomory's cut needs only an optimal simplex tableau (lesson Simplex as walking between vertices (a tiny tableau implementation)), so it applies to any model whose variables, slacks included, must be integers. So the left side is an integer, and the right side must be one as well. The right side is $3/4$ minus something that is $\ge 0$ (the slacks are $\ge 0$), so it is at most $3/4$; an integer at most $3/4$ is at most 0. So every plan satisfies

A cut in slacks is hard to read. Substitute $s_1 = 6 - d - t$ and $s_2 = 45 - 5d - 9t$: $\tfrac{3}{4}(6 - d - t) + \tfrac{1}{4}(45 - 5d - 9t) \ge \tfrac{3}{4}$, which simplifies to $2d + 3t \le 15$. Each fractional row gives its own cut, and the program prints both, then adds the one whose right-hand side has the largest fractional part (a common choice):

The model is the worked example of MIT's chapter on integer programming (section 9.8, see Further reading), with $d$ and $t$ for its $x_1$ and $x_2$; it derives the same two cuts from the same tableau, and draws them. Most models are not this kind: Gomory's own proof says a careful sequence of such cuts always ends, but in floating point the fractional parts of long rows pick up rounding error, and a "cut" built from $0.9999999$ instead of 1 can remove a real plan. Solvers Generate Many Cut Families and Choose Which to Keep


Cover and Gomory cuts are two of many cut families: rules that each produce one kind of valid inequality from one kind of structure (flow covers from flow rows, clique cuts from rows like $x_a + x_b \le 1$, and more). A solver runs several separation routines at the root and does not keep every cut it finds, since each kept cut makes every later LP bigger: the HiGHS log of lesson Reading a full MIP log line by line shows 906 cuts in HiGHS's cut pool and 39 of them in the LP at one point of its root.


You can see the effect without knowing the families. The five-year selection model (lesson Presolve: what the solver removes first states it in full: 400 projects of GridCap medium, five yearly budget rows, must-do, parent and alternative rules) solved by SCIP, the solver of the SCIP Optimization Suite that ships with OR-Tools, with its cuts on and off through MathOpt's common cuts parameter:






Same answer, as it must be: cuts never change the optimum, only how fast it is proved. Without cuts SCIP explored 1,966 nodes of its search tree instead of 718. A node is one subproblem of the branch-and-bound search: the model with some variables fixed by branching. A weaker bound prunes fewer of them.


The last line is a warning about the tools. MathOpt's cuts parameter is common to all solvers in name only: HiGHS, as bundled with OR-Tools 9.15, rejects it. The rejection also arrives badly: in OR-Tools 9.15 the exception mathopt.solve raises is an AttributeError about a missing canonical_code, a bug in the Python wrapper, and HiGHS's own reason ("cuts solve parameter unsupported for HiGHS") is only on the exception's __context__, as the last two lines show. MathOpt's parameter reference allows such a refusal: setting an effort parameter to OFF returns an error when the solver cannot switch that feature off. Lesson Common vs. solver-specific parameters, and what each solver rejects lists which solver accepts which common parameter.


Summary


  • The LP relaxation overestimates, and a cut removes its optimum without removing any plan. A valid inequality holds for every 0-1 plan; a cut is one the current LP optimum breaks.
  • A cover is a set of projects that cannot all be funded: $\sum_{i \in C} c_i > B$ gives $\sum_{i \in C} x_i \le |C| - 1$. Minimal covers give the strongest of these.
  • Separation finds a cover the LP point breaks: violated exactly when $\sum_{i \in C} (1 - x^*_i) < 1$; a greedy rule picks low $(1 - x^*_i)/c_i$ first.
  • Each round of cuts lowers the bound, and the gain tails off, so solvers cut at the root and then branch: branch-and-cut.
  • A Gomory cut comes from any tableau row with a fractional right-hand side: $\sum_j f(\bar a_j) w_j \ge f(\bar b)$, with $f(a) = a - \lfloor a \rfloor$.
  • Solvers generate many cut families and choose which to keep. On the five-year model, SCIP needed 718 nodes with cuts and 1,966 without.

Design Note: Why the Model You Write Matters More Than the Cuts the Solver Finds


Every cut in this lesson is a row the modeler could have written. The cumulative precedence form of lesson Aggregated vs. cumulative (disaggregated) forms is exactly that: a tighter formulation is a set of good cuts added before the solver starts, and it costs the solver nothing to find them. Solver cuts are a safety net for the structure you did not see. When a model's root bound is far from its best plan, look at the formulation first (big-M constants, aggregated rows), and at the cut settings only after.
