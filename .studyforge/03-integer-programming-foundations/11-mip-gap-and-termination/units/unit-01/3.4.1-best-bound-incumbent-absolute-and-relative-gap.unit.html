  17. Best bound, incumbent and gap

GridCap's planning job picks which of the medium portfolio's 400 candidate projects to fund. Last night an operator stopped it early, and the dashboard showed two figures: NPV $224,315k, gap 0.11%. The finance lead asks the obvious questions. Is this the best plan? If not, how much better could the best one be? Can we tell without running the job to the end? GridCap is a fictional utility, and its numbers are teaching data.

Every mixed-integer solver answers those questions with two numbers it keeps during the whole run: the value of the best plan it has found, and a value it has proved no plan can beat. This lesson names the two, shows how they move as the search goes on, reads them from a MathOpt result, and turns them into the gap that a dashboard prints.

The Model

The planning job solves GridCap's project-selection MILP: one yes/no decision per project, each project starting at its earliest start year. A MILP (mixed-integer linear program, lesson The problem zoo: LP, MILP, CP, NLP and how to pick) is a linear model in which some variables may only take whole-number values; here every variable is binary, 0 or 1.

Sets. $P$ the candidate projects; $Y$ the plan's years; $M \subseteq P$ the must-do projects; $\mathcal{G}$ the alternative groups, each a set of projects of which at most one may be funded; $C \subseteq P$ the child projects, each with a parent project $p(c)$.

Parameters. $v_i$, the NPV of project $i$ if it starts at its earliest start ($k); $c_{i,y}$, what project $i$ spends in year $y$ when it starts then ($k, 0 in a year it is not worked); $B_y$, the budget of year $y$ ($k).

Variables. $x_i \in \{0, 1\}$ for every $i \in P$: 1 if project $i$ is in the plan.

A MILP Solver Keeps Two Numbers: the Best Plan Found and a Bound on Every Plan

A MILP solver does not try plans one by one; the medium model has $2^{400}$ yes/no combinations. It works with LP relaxations instead (lesson The problem zoo: LP, MILP, CP, NLP and how to pick): the same model with each $x_i$ allowed anywhere between 0 and 1. An LP solves fast, and its value is at least as high as any whole-number plan's value (lesson The integrality gap, measured on GridCap gives the argument).

The search, branch and bound (lessons Branching on a fractional variable to A knapsack branch-and-bound in 116 lines), splits the problem into smaller problems called nodes. Each node fixes some variables (say $x_{P077} = 1$ in one node and $x_{P077} = 0$ in the other) and solves the LP relaxation of what is left. Along the way the solver keeps two numbers:

  • The incumbent is the best whole-number plan found so far, and its objective value. It is a real plan that obeys every row, so you could fund it today. Solvers also call its value the primal bound.
  • The best bound is a value the solver has proved no plan can beat. For a maximization it is the highest LP value among the nodes still waiting to be explored: every plan not yet ruled out lives in one of those nodes, and none is worth more than its node's LP value. Solvers also call it the dual bound. Before any branching it is the LP relaxation of the whole model.

The true optimum $z^*$, the value of the best plan, is unknown until the end, but it always sits between the two:

For a minimization everything flips: the incumbent is the lowest cost found, the best bound is a cost no plan can go below, and $\text{best bound} \le z^* \le \text{incumbent}$. In both cases the incumbent is a plan you hold, and the best bound is a promise about plans you do not hold.

The Incumbent Rises and the Bound Falls Until They Meet

bracket.py solves the model several times, each time letting HiGHS explore at most a given number of nodes (node_limit, a stopping rule lesson Stopping on gap, time, nodes or solution count covers), and prints both numbers at the stop. Each run also sets relative_gap_tolerance=0.0, so the node limit is the only thing that can stop it early. The last run has no node limit:

Read it row by row:

  • The LP relaxation, $224,870.85k, is the first bound any solver has. After the first node the bound is already lower, $224,555k. The log at the end of this lesson shows HiGHS adding cutting planes at the root (lesson Cutting planes: Gomory and cover cuts by hand): extra rows that cut off fractional points without cutting off any whole-number plan, which pulls the LP value down.
  • Down the table the incumbent never falls and the bound never rises, so the bracket $[\text{incumbent}, \text{best bound}]$ narrows. Each row is a separate run that starts from scratch, not a snapshot of one run. Within a single run the pattern holds by definition: the incumbent is the best plan found so far, and a bound once proved stays proved. Across rows nothing forces it: the pattern relies on HiGHS making the same choices in every run, so that a run with a larger node limit goes over the same ground as a smaller one before going further. A solver whose search changed from run to run could print a row with a lower incumbent than the row above it. Lesson Stopping on gap, time, nodes or solution count, in its rule Time Limits Are Not Repeatable; Node and Solution Limits Are, shows HiGHS repeating a node-limited run exactly.
  • At 12,000 nodes the incumbent is already $224,384k, the true optimum, but the solver cannot know it yet: the bound still allows plans up to $224,453k. From there on there was no better plan to find. The rest of the full run, up to 13,930 nodes, pushed the bound down until it met the incumbent, and that meeting is what proves the plan optimal.
  • At the end the two numbers are equal, and the termination reason is OPTIMAL.

So the honest answer to the finance lead, at any moment before the end, is the bracket: the best plan is worth between the incumbent and the bound. At the operator's stop, with $224,315k found and nothing worth more than $224,552k, the best plan is worth at most $237k more than the one in hand.

The 486.85 between the LP relaxation and the optimum is the integrality gap of lesson The integrality gap, measured on GridCap. Do not confuse the two. The integrality gap is a fixed property of the formulation. The gap of this lesson is a property of one moment of one run, and it closes as the run goes on.

    Check a claim against the bracket

    • a MILP run keeps an incumbent, the best plan found, and a best bound no plan can beat, and the optimum lies between them

    Not startedPassed

Problem statement

A freight company's depot-siting MILP has been running for an hour. While it runs, managers keep asking the same kind of question: "is there a plan worth at least 5,200?", or, on the cost model, "can we do it for 3,000 or less?". The solver's two numbers answer each question in one of three ways, without waiting for the end.

Write judge_claim(value, incumbent, bound, maximize) in claims.py. incumbent is the value of the best plan found so far, or None when no plan has been found yet. bound is the best bound. maximize is True for a maximization and False for a minimization. The claim is "a plan at least as good as value exists" (at least value when maximizing, at most value when minimizing). Return:

  • "found" when the incumbent already is such a plan: for a maximization value <= incumbent, for a minimization value >= incumbent.
  • "impossible" when the bound rules it out: for a maximization value > bound, for a minimization value < bound.
  • "possible" otherwise: the claim lies inside the bracket, and only more search can settle it.

With incumbent set to None, no claim is "found", and a claim the bound does not rule out is "possible": not having found a plan yet is not a proof that none exists.

  • on a maximization a claim at or below the incumbent is found, one up to the bound is possible, one above the bound is impossible
  • on a minimization the incumbent is the high end and the bound the low end, so the directions flip
  • a claim exactly at the bound is possible, since the optimum may sit on the bound
  • a claim exactly at the incumbent is found, since the incumbent itself reaches it
  • with no plan found yet, nothing is found and nothing within the bound is ruled out








Read Both Bounds From the SolveResult


mathopt.solve returns a SolveResult. Its termination field says how the run ended, and termination.objective_bounds holds the two numbers, under the names primal_bound (incumbent) and dual_bound (best bound). Two methods give them too: objective_value() is the objective of the best plan returned, and best_objective_bound() is the dual bound. With them, the gap of a maximization that holds a plan worth more than 0 is two lines:




On a run stopped after 100 nodes, read_gap.py reads the result each of these ways, then computes the gap with gap:



FEASIBLE means "a plan, not proved best"; lesson Stopping on gap, time, nodes or solution count lists every way a run can end. The primal_bound and objective_value() agree here. MathOpt's documentation of objective_value allows the primal bound to be slightly better than the returned plan's value, within the solver's tolerances, so the gap is read from objective_bounds, where both numbers come from the same moment.


A run without a plan is the case code must not get wrong. Cut 2027's budget to $1,000k, below what the must-do projects spend that year, and solve:



With no plan, the primal bound of a maximization is $-\infty$ (for a minimization, $+\infty$), and objective_value() raises an error rather than invent a number. Here the dual bound is $-\infty$ as well, because the solver proved that no plan exists at all. A run can also stop on a limit before it has found any plan; lesson Stopping on gap, time, nodes or solution count shows how its result says so. Either way the rule for code is the same: check has_primal_feasible_solution(), or that the primal bound is finite, before you read a plan's value or compute a relative gap.


The Absolute Gap Is in the Objective's Units


The absolute gap is the distance between the two bounds:



The absolute value makes it the same formula for a maximization and a minimization. It is in the objective's units, which in this model are $k of NPV. The 237.0 above says: no plan is worth more than $237k above the one in hand. It is a guarantee about the plan's value, and a planner can weigh it against money they understand, such as the cost of a single project.


It is also only an upper limit on what the incumbent leaves behind. The true optimum can be anywhere inside the bracket, and in this run it was $69k above the incumbent ($224,384k against $224,315k), not $237k. Only the bound was too high.


The Relative Gap Divides by a Number Each Solver Chooses


The relative gap puts the absolute gap on a scale, so that one tolerance can serve a model worth $300k and a model worth $3B:



What the reference value is depends on the solver. MathOpt's own documentation of relative_gap_tolerance says so: the normalization is solver-dependent, for example dividing by the incumbent's objective value. denominators.py stops HiGHS and SCIP (another MILP solver that MathOpt runs, as GSCIP) at the first plan each finds, on the selection model (max NPV) and on a second model that minimizes capex subject to an NPV of at least $200,000k. It prints each solver's own final gap line from its log, then the gap divided three ways:



Match each "log says" against the three columns. In these four runs:


  • HiGHS divides by the incumbent. 2.4% matches 2.3966% (not 2.3405%), and 0.447% matches 0.4468% (not 0.4488%), for the maximization and the minimization alike. HiGHS's documentation says the same: its option mip_rel_gap is the tolerance on $\lvert ub - lb \rvert / \lvert ub \rvert$, where $ub$ is the primal bound of the minimization HiGHS solves internally, and its terminology page calls the gap relative to the primal bound the better measure.
  • SCIP divides by the smaller of the two in size. In the maximization the incumbent is the smaller, and 613.69% matches it; in the minimization the bound is the smaller, and 0.95% matches 0.9478%, not the 0.9389% that dividing by the incumbent would give.


Three things follow:


  1. The same tolerance does not mean the same stop. A relative tolerance of 0.01% asks HiGHS and SCIP for slightly different things. The difference is tiny when the gap is tiny, and large when it is not.
  2. A relative gap can exceed 100%. SCIP's first plan, $44,958k, was far below its bound, and the gap is six times the plan's value. Nothing caps it at 100%.
  3. Near zero, a relative gap means little. When the incumbent is 0, dividing by it gives infinity, and when the incumbent and the bound have opposite signs, no division describes the distance well. Profit models that hover around zero are judged by the absolute gap.


The relative gap is a ratio, and a ratio is only as meaningful as what it divides by. This course computes it the way HiGHS does, divided by the incumbent, and says so wherever it prints one.

Problem statement


A hospital's nurse-rostering MILP runs every Sunday night with a time limit. The service that starts it stores a short report of each run, built from the SolveResult that mathopt.solve returned. Some weeks the run ends with a plan, some weeks it stops before finding one, and once a year the rules contradict each other.


Write read_gap(result) in gap.py. Read the two numbers from result.termination.objective_bounds: primal_bound (the incumbent's value) and dual_bound (the best bound). Return a dict with four keys:


  • "incumbent": the primal bound as a float, or None when it is infinite (no plan).
  • "bound": the dual bound as a float, or None when it is infinite.
  • "absolute": $|\text{bound} - \text{incumbent}|$, which is positive for a maximization and a minimization alike, or math.inf when either number is missing.
  • "relative": the absolute gap divided by $|\text{incumbent}|$, the way HiGHS divides. It is 0.0 when the absolute gap is 0, math.inf when the incumbent is 0 and the absolute gap is not, and math.inf when either number is missing.


The result does not say whether the model was a maximization or a minimization, and your function does not need to know. math.isinf(x) tells you whether a float is infinite.

Summary


  • A MILP solver keeps two numbers. The incumbent is the best plan found (the primal bound); the best bound is a value no plan can beat (the dual bound). The optimum is always between them.
  • The incumbent rises and the bound falls until they meet. Meeting is the proof of optimality; the last part of a run often finds no better plan and only lowers the bound.
  • Read both bounds from the SolveResult, in termination.objective_bounds. With no plan the primal bound is infinite and objective_value() raises.
  • The absolute gap is in the objective's units: no plan is better than the incumbent by more.
  • The relative gap divides by a number each solver chooses: HiGHS the incumbent, SCIP the smaller of the two. It can exceed 100%, and near zero it means little.
  • The integrality gap is not this gap. One belongs to the formulation; the other to a moment of a run.

Design Note: Report the Bracket, Not Only the Plan


A dashboard that shows only the incumbent's NPV hides the most useful fact a stopped run has: how much better a plan could be. Reporting the incumbent, the bound and the absolute gap in money costs one line, and it turns "is this the best plan?" from a question nobody can answer into a number finance can weigh. The relative gap is a good stopping rule (lesson Stopping on gap, time, nodes or solution count), but a poor sentence for a planner: "within $237k" says more than "within 0.11%".
