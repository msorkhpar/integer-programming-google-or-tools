Lesson Hints, assumptions and SufficientAssumptionsForInfeasibility met CP-SAT's assumptions: guard each rule with a Boolean flag, assume every flag true, and when the model is infeasible the solver names a set of flags that cannot all hold. On GridCap small at 60% of the budget it named all 28 flags, and a deletion filter cut them to 3. The Budget Lock scenario is a different case: it has three conflicts (lesson IIS with MathOpt, gurobipy and Pyomo), and the planners want all of them, in the rows they can change, with as few solves as possible. This lesson runs the same scenario through CP-SAT. It lists every conflict, controls which conflict a filter returns, filters whole families of rules before single rows, and finds the fewest rules to switch off. GridCap is a fictional utility; none of its numbers are real.

The Model

The model of lesson Infeasible, unbounded, or the solver can't tell with one change, marked: every row except once$_i$ holds only when its flag is 1. convert.to_cpsat(model, flagged=...) copies the MathOpt model into CP-SAT row for row, which works because CP-SAT works over the integers and all of GridCap's data are integers, and guards each named row with .only_enforce_if(flag).

Sets. As in lesson Infeasible, unbounded, or the solver can't tell, plus $\mathcal{R}$, the flagged rows: every row except once$_i$ (34 on the Budget Lock scenario). $\leftarrow$ new

Parameters. As in lesson Infeasible, unbounded, or the solver can't tell, with the Budget Lock scenario's values.

Variables. $x_{i,t} \in \{0, 1\}$ for $i \in P$, $t \in T_i$, as before; and $f_r \in \{0, 1\}$ for every $r \in \mathcal{R}$: rule $r$ is on. $\leftarrow$ new

Objective. None for the conflict questions: each is a feasibility question, so the copy's objective is cleared. The last section maximizes $\sum_{r \in \mathcal{R}} f_r$.

Constraints. once$_i$ as in lesson Infeasible, unbounded, or the solver can't tell, and every other row of that lesson guarded by its flag ($f_r \Rightarrow \text{row } r$):

Here $\ell_r \le a_r^\top x \le u_r$ is row $r$ of lesson Infeasible, unbounded, or the solver can't tell written with both of its bounds (one of them infinite for an inequality). For example, $f_{\text{budget}_{2028}} \Rightarrow \sum_i \sum_t c_{i,2028-t}\, x_{i,t} \le 6{,}000$. The assumptions are $f_r = 1$ for every $r$ in the set being asked about. A flag that is not assumed is a free variable, so the solver may set it to 0 and switch its rule off.

Assumptions Need Flags, One Worker and a Map From Index to Name

Lesson Hints, assumptions and SufficientAssumptionsForInfeasibility set out the mechanics, and conflict here uses them unchanged. It builds the flagged copy, assumes the named flags, solves with one worker, and turns the indices the solver returns back into row names:

Three points carry over from lesson Hints, assumptions and SufficientAssumptionsForInfeasibility and the CP-SAT troubleshooting page. sufficient_assumptions_for_infeasibility() returns variable indices, not names. Assumptions do not work with parallel search, hence one worker. And the set is sufficient: it is reduced, but not promised to be minimal. A common claim says it returns "a minimal core". The troubleshooting page does not say that, and lesson Hints, assumptions and SufficientAssumptionsForInfeasibility measured a set of all 28 flags.

The flagged model is built afresh for every question, so that no assumption from an earlier question stays behind (model.clear_assumptions() would also do).

When the named sets are small, listing every conflict is cheap. Switch off one named row (one the planners set, when there is one), ask again, and repeat:

The three conflicts of lesson IIS with MathOpt, gurobipy and Pyomo, in 4 solves. The HiGHS loop of that lesson needed 211: a deletion filter costs one solve per active row, and each conflict found switched one row off, so the three filters cost 70, 69 and 68 solves, plus 4 checks of whether the active rows were still infeasible (70 + 69 + 68 + 4 = 211).     Which roster rules clash?

    • rules guarded by flags, assumed, solved with one worker, read back by index

    Not startedPassed

Problem statement

A hospital ward builds its weekly nurse roster with CP-SAT. Three kinds of rules apply:

Rule nameRule
cover_<day>at least need[day] nurses work on that day
max_<nurse>the nurse works at most max_shifts[nurse] days in the week
off_<nurse>_<day>the nurse does not work on that day (a granted request)

When no roster exists, the ward manager wants the rules that clash, by name. Write the formulation first: a 0/1 variable per nurse and day, and each rule as one constraint guarded by its own Boolean flag. Then write named_conflict(nurses, need, max_shifts, days_off):

  • build the model, assume every flag, and solve with one worker;
  • if a roster exists, return None;
  • otherwise return the sorted names of the rules whose flags the solver reports in sufficient_assumptions_for_infeasibility().

nurses is a list of names (no underscores), need maps each day of the week (an integer) to the nurses needed, max_shifts maps each nurse to a limit, and days_off is a list of (nurse, day) pairs. A day off on a day that is not a key of need forbids nothing: it gets no rule and no name. CP-SAT here only decides whether a roster exists, so there is no objective and no gap tolerance to set. The set the solver reports is sufficient, not always minimal, so the tests check that the names you return are infeasible together and include the rules that must be there. About twenty lines.

The Order of a Deletion Filter Chooses Which Conflict You Get


When the named set is large, or when you want a conflict made of certain rows, run the deletion filter yourself on the flags. minimal is lesson Hints, assumptions and SufficientAssumptionsForInfeasibility's filter. As lesson IIS with MathOpt, gurobipy and Pyomo showed, it keeps the conflict whose rows come last in its order. Here it runs over all 34 flags twice, once with the rows planners set (budgets, crews, floors, overrides) first and once with them last:






Tested first, the planners' rows are dropped whenever another conflict can hold without them. The 2028 rows and the overrides go, and P017's conflict survives, because its must-do row is tested late. Tested last, the must-do row is dropped early, and the conflict that survives is the overrides' one, made almost entirely of rows the planners set. For a message to the board, the second order gives the conflict they can act on. Either way the cost is one solve per flag.


Filter Whole Families First, Then the Rows Inside Them


Lesson Hints, assumptions and SufficientAssumptionsForInfeasibility's design note suggested a cheaper pass on large models: one switch per rule family first, then single rows only inside the families that matter. A family here is the prefix of a row's name: budget, crews, floor, force, must, alt, after. The first pass is a deletion filter whose items are whole families:






Seven solves to learn that crews and must-do rows alone are enough for a conflict, then 19 to filter the 19 rows of those two families: 26 solves against 34. The saving grows with the model: a family pass costs one solve per family, however many rows each family holds. The first pass drops the after family first, which is why the override conflicts (which need P023's precedence row) do not survive it. Problem statement


A wind farm's maintenance model has thousands of rules in a few families: sensor checks per turbine, an uptime target, quarterly budgets, staffing minimums. A deletion filter over every rule would cost one solve per rule. The reliability engineer wants the cheaper two-pass version:


  1. Families. Go through the families in the given order. Switch one family off (all its rules) while the families still kept stay on. If the rest is still infeasible, drop that family for good. If it becomes feasible, keep the family.
  2. Rules. Go through the rules of the kept families, in the given order (family by family, rule by rule). Run the deletion filter on them, with every dropped family still switched off.


You get the families as a dict from family name to its list of rules, and an oracle, infeasible(rules) -> bool, which says whether the model has no solution with exactly the rules in the set switched on. Write two_pass(families, infeasible) returning (kept, conflict): the kept family names and the rules of the conflict, both in the given order. The model is known to be infeasible with every rule on. No solver runs and no gap tolerance is involved: the oracle answers each question exactly. About fifteen lines.

The Fewest Rules to Switch Off Is an Optimization, Not an Assumption


A minimal conflict answers "which rules clash?". The planners' next question is "what is the fewest rules we could drop to get a plan?". That is a different set: one that meets every conflict (it hits each one), rather than one conflict. Assumptions do not answer it. An objective does. Make every flag free, with no assumptions, and maximize the number of flags left on:






Two rows: the 2030 transmission crews (P017 can then start in 2030) and the board's P032 override, which is in both override conflicts. The counting objective of lesson Elastic constraints and feasibility relaxation also found 2, with a different pair, must_P017 and force_P023. Both pairs hit all three conflicts, and the count proves no single row does. When several answers tie, a solver returns one of them, so a report should say "for example" or add a rule that breaks the tie, such as weights that make must-do rows expensive. The CP-SAT troubleshooting page makes a similar point about minimality. For a set that is truly smallest, optimize over the literals rather than rely on the sufficient set.


Summary


  • Assumptions need flags, one worker and a map from index to name. The set the solver names is sufficient, not promised minimal.
  • Here the solver named a minimal set at once, so every conflict cost one solve: the three conflicts in 4 solves, against 211 with HiGHS and a filter. Check a named set with a filter before reporting it as minimal.
  • The order of a deletion filter chooses which conflict you get. Put the rows you want named last. One solve per flag.
  • Filter whole families first, then the rows inside them: 7 + 19 = 26 solves instead of 34.
  • The fewest rules to switch off is an optimization, not an assumption. Maximize the flags left on. Two rows here, and the answer ties with lesson Elastic constraints and feasibility relaxation's.

Design Note: Ask the Solver for the Cheap Part, Check the Rest Yourself


CP-SAT's sufficient set costs nothing extra: it comes with the INFEASIBLE answer. Whether it is minimal costs one solve per member to check. A conflict finder that uses the free answer, then checks it before reporting, gets the speed of the first and the guarantee of the second. When the check finds the set already minimal, as on every set here, it has cost a few solves. When it does not, as in lesson Hints, assumptions and SufficientAssumptionsForInfeasibility, the planners never see 28 rules called "the conflict".
